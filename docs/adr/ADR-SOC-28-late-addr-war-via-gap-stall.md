# ADR-SOC-28: late-addr 访存类与 WAR 的 gap-stall 表达（取消 WAR 硬件状态）

> **日期**: 2026-10-29
> **Owner**: ArchForge Team
> **影响**: 自研 ISA 的依赖层 WAR 机制；依赖状态面积；编译器 A-1/A-4 pass
> **类别**: ISA 依赖管理 / 正确性机制
> **实施**: OpenSpec change（待建）—— B-0 / B-2 / B-3
> **关联**: [`36-new-isa-dependence-layer-design.md`](../architecture/36-new-isa-dependence-layer-design.md) §4.1.5 / §4.1.6（本 ADR 的完整推导 + 可复现验证脚本）· [`40-new-isa-spec-skeleton.md`](../architecture/40-new-isa-spec-skeleton.md) §4.5 / §4.2 · [`ADR-SOC-27`](./ADR-SOC-27-compiler-driven-dependence-management.md)（父决策）

## 1. 背景

不变式 **D-1**（源锁存窗口 ≤ 写可见延迟）意味着：只要 `D_c ≤ L_w,min`，**按序发射的读者→写者序列不产生 WAR** ⇒ 可以不设 WAR 计数器（NVIDIA 需要）与 WAR scoreboard（学术方案需要）。

但 D-1 对**访存**是紧的：NVIDIA 的访存指令把源读取推迟到 **+11 拍**（实测），而 `L_w,min = 4` ⇒ `D_mem = 11 > 4` ⇒ **访存类豁免 D-1**。pointer-chasing 类 kernel 的地址源无法 4 拍内就绪。

这不是可以忽略的角落：Q-9 的三档实测判据是「若全标准访存相对 NVIDIA 口径的吞吐损失 > 15%，则必须依赖豁免类」⇒ **必须有一条机制兜住它**。

问题：**这条机制要占多少硬件与编码？**

## 2. 决策

### D1 —— 设立「延迟地址访存」（late-addr）豁免类

| 项 | 内容 |
|---|---|
| 触发 | **opcode 变体**（`LD.LATE` / `ST.LATE`）—— **不占控制位** |
| `D_mem` | **11**（豁免 D-1） |
| 编译器判定 | 地址依赖无法在 `D_mem = 4` 内就绪 ⇒ 标 late-addr；否则用标准访存 |

### D2 —— **WAR 由 gap 内的 `stall` 表达，取消全部 WAR 硬件状态**

**ISA 不提供 WAR 计数器 / WAR scoreboard / WAR 槽位。**

**机制**（36 号 §4.1.6 完整推导）：

```
记号：slot(k) = 指令在 warp 指令流中的序号
      A(k)    = Σ_{i<k} stall(i)
      t(k)    = slot(k) + A(k)          ← 实际发射时刻
stall 语义：  本指令发射「后」开始倒数 ⇒ 推迟的是「下一条」指令

WAR 条件：  t(W) + L_w,min > t(R) + D_mem
           ⇔  d + Σ_{R ≤ i < W} stall(i) ≥ 8        （d = slot(W) − slot(R)）
```

| 项 | 结论 |
|---|---|
| **条件** | `d + Σ_{R≤i<W} stall(i) ≥ 8` |
| **落点** | **gap `[R, W)` 内**，优先 **`R` 自身**（`d = 1` ⇒ `R.stall ≥ 7`） |
| **⚠ 禁止写法** | 在**写者 `W`** 上置 `stall` —— `W` 上的 `stall` 推迟的是 `W` 的**后继**，保护**恒为 0** |
| **可表达性** | 最大需求 `D_mem − L_w,min = 7 ≤ 15` ⇒ **恒可由 4-bit `stall` 表达** |
| **导出的可表达性条件** | **`D_c − L_w,min ≤ 15`** —— **本 ADR 提供的是「推导」**（gap-stall 可表达性）；**规范条款归 [`ADR-SOC-27`](./ADR-SOC-27-compiler-driven-dependence-management.md) §2 D2 的 D-1′ 行**，**本 ADR 不另立不变式、不重复条款** |

### D3 —— 实例级义务（**逐类检查抓不住实例级的 `d`**）

| # | 义务 | 违反时的退路 |
|---|---|---|
| **W-1** | 每个 late-addr 读者 `R` 与其每个后继写者 `W`：`d` 与 gap 累计 `stall` **必须编译期可确定**，且满足 `d + Σ ≥ 8` | 编译器**不得**标注 late-addr（回退标准访存） |
| **W-2** | `R` 与 `W` 必须**同基本块**（或编译期可确定固定距离的循环体） | 同上 |
| **W-3** | `W` 若本身走 SB 槽（写可见远晚于 `issue + 4`），条件自动更宽松 ⇒ 按最坏 `L_w = 4` 计算即安全 | — |

### D4 —— 面积收益

**取消 `WAR[2] × 6 = 12 bit/warp`** ⇒ 依赖状态 **65 → 53 bit/warp** ⇒ **0.149% → 0.121% RF**（48 warp/SM 基数）。

### D5 —— 与 NVIDIA 为何不同

NVIDIA 用 WAR 计数器，是因为它的 WAR 释放点是**硬件内部行为**（+11/+14 拍）且其调度器允许更激进的乱序。本 ISA 的 `D_mem` 是**架构常量**、发射严格按序 ⇒ 静态可算 ⇒ 计数器是多余的。

## 3. 选项对比

| # | 选项 | 结论 | 理由 |
|---|------|:----:|------|
| **1** | **专用 WAR 槽**（36 号 Q-1 原案：2 槽 × 6 bit 独立于 SB） | ❌ 否决 | +12 bit/warp；且释放事件与 SB 不同 ⇒ 分配复杂；**本 ADR 的推导证明它是多余的** |
| **2** | **硬件 WAR scoreboard**（按寄存器记录 pending 读者） | ❌ 否决 | 需 per-warp 寄存器表项（> 16 bit/warp），且把 A-1 的"硬件兜底"扩大到时序域，与 D-3 的边界冲突 |
| **3** | **完全禁止 late-addr**（访存一律 `D_mem ≤ 4`） | ❌ 否决 | pointer-chasing 类 kernel 的 issue 端等待不可接受（Q-9 的净效果分析：**换"所有 kernel 少 7 拍写者阻塞"，代价是地址链 kernel 的发射端等待**） |
| **4** | **每域 1 个专用 WAR 槽（合并计数）** | ❌ 否决 | 并发 late-addr 时写者被阻塞到**所有**读者都锁存源为止（并集语义）⇒ 用性能换 3 个编码位，且**预设了"槽分域"这个尚未裁决的问题** |
| **5** | **gap 内 `stall` 表达（本 ADR）** | ✅ **采纳** | **零硬件状态、零编码位**；面积 0.121% RF（比 Q-1 原案再降 0.028%）；推导可机械验证（36 号内嵌脚本，输出与正文逐字节一致） |

## 4. 后果

### 4.1 正面

- **面积再降 0.028% RF**，且**没有引入任何新的架构状态**（ISA 的架构状态清单因此更短）；
- **不变式体系统一**：D-1 / D-1′ 都是"对着 E-14 延迟表核对"的**同一种检查**，不需要第二套机制（**D-1′ 的规范条款在 ADR-SOC-27 §2 D2，本 ADR 只提供推导**）；
- **编译器负担可控**：W-1/W-2 的判定发生在**调度 pass 之后**（`d` 是基本块内的静态量，gap 累计 `stall` 是编译器自己插入的、天然已知）⇒ **可判定**，不是无法验证的散文；
- **与 NVIDIA 的差异被显式记录**（D5），避免后人误以为"漏做了 WAR 计数器"。

### 4.2 负面

- **失去了 late-addr 的硬件兜底**：若编译器违反 W-1/W-2，**没有硬件能救** ⇒ 这类错误直接表现为程序结果错误（对比 A-1/A-2 让复用提示错只损失性能）；
- **flush 语义简化但需说明**：NV 建模后端需要"WAR 槽在分支 flush 时强制清零"，新 ISA **不需要**（`stall` 是编译期常量，与运行时是否执行无关 ⇒ 无悬挂计数）—— 这是一个**只有理解了两者差异的人才会发现的收益**，需写进规范；
- **Q-1 作废**：依赖 36 号 Q-1 的读者需改按本 ADR；
- **D-1′ 成为新的紧约束**（条款在 ADR-SOC-27 §2 D2）：豁免类的 `D_c` 不得超过 `L_w,min + 15` ⇒ v2 的矩阵类（`L_w` 32–64）**必须走 SB 槽**，不能靠 `stall`。

### 4.3 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| **编译器误判 `d` 不可静态确定** ⇒ 大量 late-addr 被回退 ⇒ MLP 收益丢失 | 中 | W-2 的判定做成"能证明就标、不能证明就不标"；用 Q-9 的三档实测监控 late-addr 命中率 |
| **`stall` 落点写错**（写成在 `W` 上）⇒ 静默的 WAR 事故 | **高** | 40 号 S-DEP-2a 明确禁止写法 + 附录 B 检查 14；36 号内嵌脚本作为**回归锚例** |
| 两类 `stall` 义务（RAW + WAR）叠加时溢出 4-bit | 中 | **合成规则 = 取 max**（两者都是下界），且各自 ≤ 15 ⇒ `max ≤ 15` 恒可表达（40 号 S-DEP-2b） |
