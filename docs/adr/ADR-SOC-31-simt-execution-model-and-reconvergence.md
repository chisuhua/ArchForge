# ADR-SOC-31: SIMT 执行模型 —— wave 32、EXEC/VP 谓词体系、编译器显式标注汇合点

> **状态**: 📋 Proposed（**待签批**）
> **日期**: 2026-10-29
> **Owner**: ArchForge Team
> **影响**: 自研 ISA 的执行模型、架构状态清单、发散/汇合语义、谓词化方式
> **类别**: ISA 执行模型
> **实施**: OpenSpec change（待建）—— B-0 / B-1 / B-5
> **关联**: [`40-new-isa-spec-skeleton.md`](../architecture/40-new-isa-spec-skeleton.md) §1（本 ADR 的规范条款）· [`38-new-isa-dual-domain-structure.md`](../architecture/38-new-isa-dual-domain-structure.md) §3.1.1b（谓词文件）· [`ADR-SOC-30`](./ADR-SOC-30-isa-encoding-48-64-variable-length.md)（`P` 变体的编码载体）· [`ADR-SOC-29`](./ADR-SOC-29-dual-domain-scalar-vector-structure.md)（双域条件码）
> **取代**: 无
> **关联争议**: 与 ADR-SOC-30 的耦合：谓词化**不占字段**、改用 **opcode 变体**（`op[7:6]=10` 段）—— 这正是 `VOP3` 恰好 64 bit 的直接后果

---

## 1. 背景

「依赖管理由编译器静态承担」这条主线（ADR-SOC-27）有一个前提：**ISA 的执行语义是确定的、编译器可静态推理的**。而 SIMT 的**发散与汇合**恰是 GPU 语义里最依赖硬件/编译器协同的部分。

三种既有做法：

| 做法 | 汇合点如何确定 | 硬件复杂度 | 编译器复杂度 |
|---|---|:---:|:---:|
| **post-dominator 自动汇合**（PTX-EMU 的做法） | 硬件/前端需 CFG 信息 | 高（要算 post-dominator） | 低 |
| **显式 join 标记**（本 ADR） | **编译器插入标记** | **低（一个栈）** | 中（要插标记） |
| **token 机制**（GPU 硬件常见） | 硬件维护 token 计数器 | 中 | 低 |

PTX-EMU（39 号 §1.4）用 CFG post-dominator 计算汇合点 —— 那是**解释器**的做法：它有整张 CFG。硬件做同样的事需要把 CFG 信息带进流水线。

## 2. 决策

### D1 —— wave 宽度 = 32

**`WAVE_SIZE = 32`**（架构常量）。
理由：与 PTX-EMU（32 lanes）对齐以支撑**差分验证**；CDNA 式 64 留作**新主版本**（§0.3 版本政策：改 wave 宽度 = ISA 身份改变）。

### D2 —— 架构状态清单（**完整枚举**）

| 状态 | 位宽 / 数量 | 写者 |
|---|---|---|
| `SGPR[128]` / `VGPR[256]` / `AccVGPR[256]` | 见 ADR-SOC-29 | — |
| **`EXEC`** | **32 bit**（逐 lane 掩码） | **仅** `SOPP.WREXEC` / `SOPP.SAVEEXEC` 与发散栈 |
| **`SCC`** | **1 bit** | 标量比较类 |
| **`VP[8]`** | **8 × 32 bit**（逐 lane 掩码） | **仅** 向量比较类 |
| `PC` | per-warp | 控制流 |
| **发散栈** | 实现定义深度（≥ 8 层） | 硬件 |
| **`SB[8]`** | 8 × 6 bit | 硬件（见 ADR-SOC-27） |
| `stall` | 4 bit | 指令字段载入 |

⇒ **存在表外状态并影响可观察行为 ⇒ 规范不成立**（40 号 A-EXEC-2）。

### D3 —— 谓词化：**opcode 变体，不设谓词字段**

| 项 | 规定 |
|---|---|
| **向量谓词化** | 每个 `VOP*` 类的 `op[7:6]=10` 段为 **`P` 变体**（64 项），语义 = "**在 `EXEC ∧ VP[0]` 下执行**"；其余段仅受 `EXEC` 约束 |
| **标量谓词化** | v1 **不支持** ALU 级谓词化；条件执行 = `SOPP.CBRANCH` + `SCC`；值选择 = `SOPC` + `S_CSELECT` |
| **比较目标** | 比较类用 opcode 变体指定 `VP[k]`（v1 仅 k=0/1），**不设独立的谓词目标字段** |
| **v1 限制** | **只有 `VP[0]` 可作谓词**；`VP[1..7]` 供比较链与 `V_CNDMASK` 使用 |

> **⇒ 为什么用 opcode 变体而不是谓词字段**：`VOP3` 已**恰好装满 64 bit**（`11+32+21`）；加 3-bit 谓词字段 ⇒ 升 80-bit ⇒ **全部向量代码 +25% 取指带宽**。**用 64 项 opcode 换 3 bit 字段**是划算的交换。
> **⇒ 代价（已记录）**：不是每条向量指令都有 `P` 变体；无 `P` 变体的指令需谓词化时，编译器降级为分支 + `JOIN`（性能代价，正确性无影响）。

### D4 —— 发散与汇合：**编译器显式插入 `JOIN`**

| 项 | 规定 |
|---|---|
| 发散表示 | 硬件维护 **per-warp 发散栈**；条件分支按 `EXEC ∧ cond` 分裂，`EXEC` 随之更新 |
| **汇合点** | **编译器显式标注**：插入 `SOPP.JOIN`（48-bit，`imm16` = join-id） |
| 汇合语义 | `JOIN` 从栈顶弹出到最近的**同一 join-id** 条目并恢复其 `EXEC` |
| 栈空 | `JOIN` 遇空栈 = **未定义行为**（编译器必须配对） |
| 嵌套 | 任意嵌套，深度上限实现定义（≥ 8） |

> **⇒ 为什么不用 post-dominator 自动汇合**：硬件做 post-dominator 需要 CFG 信息 ⇒ 显式 `JOIN` 把这段逻辑交给编译器，**硬件只需一个栈**。这与"编译器驱动依赖层"的主线一致。

### D5 —— 发射顺序（**全部静态推理的前提**）

**warp 内指令严格按序发射**；warp 间由调度器择一。
⇒ **任何依赖 `D`/`L_w` 的静态推理（ADR-SOC-27 / ADR-SOC-28）都以这条为前提**；若未来允许乱序发射，**全部不变式须重证**。

### D6 —— `stall` 的计数单位

**按「本 warp 的发射机会」计数**，不是 wall-clock 周期。
⇒ warp 被换出时只可能**增加**实际经过时间 ⇒ 编译器按发射距离做的静态推理**保守成立**。

## 3. 选项对比

| # | 选项 | 结论 | 理由 |
|---|------|:----:|------|
| **1** | **wave = 64**（CDNA 式） | ❌ 否决（v1） | 与 PTX-EMU（32 lanes）对齐才能做差分验证；且 64 会使 `EXEC`/`VP` 宽度与语义全变 ⇒ 属"新主版本"，不宜在 v1 冻结 |
| **2** | **post-dominator 自动汇合** | ❌ 否决 | 硬件需 CFG 信息 ⇒ 硬件复杂度与 ISA 语义耦合；且与"编译器驱动"主线不一致 |
| **3** | **硬件 token 机制** | ❌ 否决 | 硬件要维护 token 计数器与活跃掩码栈；本 ISA 的 `JOIN` 方案把这件事交给编译器，硬件只需一个栈 |
| **4** | **显式 `JOIN` + wave 32 + opcode 变体谓词化（本 ADR）** | ✅ **采纳** | 硬件状态最少（一个栈 + `EXEC` + `VP`）；与 39 号的差分验证路线对齐；与"编译器驱动依赖层"主线一致 |
| **5** | **指令级谓词字段（3 bit）** | ❌ 否决 | `VOP3` 恰好 64 bit ⇒ 加字段必升 80-bit ⇒ 向量代码取指带宽 +25%；改用 opcode 变体更划算 |

## 4. 后果

### 4.1 正面

- **架构状态清单短且完整**：无隐藏状态 ⇒ 规范可判定；
- **硬件实现最简**：发散 = 一个栈 + 一个掩码寄存器；
- **与差分验证路线兼容**：wave 32 与 PTX-EMU 对齐 ⇒ B-1 的差分框架可直接搭；
- **谓词化不占字段** ⇒ 向量取指带宽不受影响。

### 4.2 负面

- **编译器必须插 `JOIN`** ⇒ 控制流翻译多一步，且**插错 join-id = 未定义行为**（不是"性能下降"，是**正确性事故**）；
- **只有 `VP[0]` 可作谓词** ⇒ 多谓词场景（v1.1）需降级为分支；
- **wave 32 的占用率问题**：宽 wave 的寄存器压力更小，但小 wave 的 latency hiding 能力较弱 ⇒ 需在 B-4 的 MCOS 模型中验证；
- **`JOIN` 与分支目标的交互**需要额外规定（如 `JOIN` 必须在基本块末尾）。

### 4.3 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| **`JOIN` 插错 / 漏插** ⇒ 挂起或错误归并 | **高** | 汇编器可校验「每个发散路径恰好配对一个 `JOIN`」（join-id 唯一性 + 栈平衡检查）；40 号 S-DEP 之外新增实现契约 |
| **谓词化覆盖率不足** ⇒ 编译器大量降级为分支 | 中 | 统计 `P` 变体的实际使用比例（V6）；必要时 v2 走 `EXT` 携带谓词号 |
| wave 32 的 latency hiding 不足 | 中 | B-4 的 MCOS 模型 + Q-9 三档实测 |
| 差分验证对不上 ⇒ 误判为 ISA 缺陷 | 中 | 39 号 §1.4 已列 PTX-EMU 的三处已知偏差（原子无序 / 逐 lane 串行 / 谓词非位）⇒ 差分用例须排除这三类 |
