## 1. 执行模型

### 1.1 执行单元与 wave

| 项 | 规范值 | 备注 |
|---|---|---|
| **wave 宽度** | **32 lanes**（`WAVE_SIZE = 32`，架构常量） | 采 39 号 B-4 建议：与 PTX-EMU（32 lanes）对齐以支撑差分验证；CDNA 式 64 留作新主版本 |
| 发射粒度 | **每拍 1 条指令 / warp**（每 warp 一个发射口） | `yield` 位可让出该拍 |
| 发射顺序 | **warp 内严格按序发射**；warp 间由调度器择一 | **这是 §4 全部静态推理的前提**，不得变更 |
| PC | **per-warp** | 无 per-lane PC（发散由 EXEC + 栈表达） |

> **⇒ 架构约束 A-EXEC-1**：**warp 内指令按程序顺序发射。** 任何依赖 `D`/`L_w` 的静态推理（§4）都以这条为前提；若未来允许乱序发射，§4 全部不变式须重证。

### 1.2 架构状态清单（**完整枚举，否则不算规范**）

| 状态 | 位宽 / 数量 | 读 | 写 | 备注 |
|---|---|---|---|---|
| `SGPR[128]` | 128 × 32 bit | 标量/向量指令 | 标量指令、`V_READFIRSTLANE` | §2 |
| `VGPR[256]` | 256 × 32 bit | 向量指令 | 向量指令 | §2 |
| `AccVGPR[256]` | 256 × 32 bit | 矩阵类（v2） | 矩阵类（v2） | v1 预留，不可由普通指令寻址 |
| **`EXEC`** | **32 bit**（逐 lane 掩码） | 硬件（发射时） | **仅** `SOPP.WREXEC` / `SOPP.SAVEEXEC` 与发散栈 | §1.4 |
| **`SCC`** | **1 bit** | 标量分支/选择 | `SOPC` 比较类 | 标量域唯一条件码 |
| **`VP[2]`** | **2 × 32 bit**（逐 lane 掩码） | 向量谓词化执行、`V_CNDMASK` | **仅** 向量比较类（`VOP2` 比较组） | **独立谓词文件**，不在 SGPR 内（38 号 §3.1.1b）；**索引字段 3 bit 保留** ⇒ v2 可扩到 8 个而无需改编码 |
| `PC` | per-warp | — | 控制流 | |
| **发散栈** | 实现定义深度（≥ 8 层） | 硬件 | 硬件（`PUSH`/`POP` 由控制流触发） | §1.4 |
| **`SB[8]`** | 8 × 6 bit 计数器 | 硬件 | 硬件（issue +1 / writeback −1） | §4.3 |
| `stall` | 4 bit（每 warp） | 硬件 | 指令字段载入 | §4.2 |
| 内存可见性状态 | per-warp 在飞访存计数 | 硬件 | 硬件 | §5 |

> **⇒ 架构约束 A-EXEC-2**：**上表是 ISA 的全部架构状态。** 存在表外状态并影响可观察行为 ⇒ 规范不成立。
> **⇒ 显式排除（oracle 审查追加，防误读）**：**MCOS / 操作数供给槽（33 号）不是架构状态** —— 它是**纯微架构**结构，其值恒等于 RF 当前值（A-1）、且在寄存器改写时失效（A-2）⇒ **不改变任何可观察值**，故**不列入上表**。实现方不得因 A-EXEC-2 而禁止 MCOS。

### 1.3 谓词化

| 项 | 规范 |
|---|---|
| **标量谓词化** | v1 **不支持** ALU 级谓词化（无 `@scc` 前缀）。条件执行 = `SOPP.CBRANCH` + `SCC`；值选择 = `SOPC` + `S_CSELECT` |
| **向量谓词化** | **由 opcode 变体表达，不设谓词字段**：每个 `VOP*` 类的 `op[7:6] = 10` 段为 **`P` 变体**（64 项），语义为"**在 `EXEC ∧ VP[0]` 下执行**"；其余段无谓词（仅 `EXEC`） |
| 实际执行掩码 | 非 `P` 变体：`EXEC`；`P` 变体：**`EXEC ∧ VP[0]`** |
| 比较写哪个谓词 | 比较类指令用 opcode 变体指定目标 `VP[k]`（v1 仅 k = 0/1），**不设独立的谓词目标字段** |
| v1 限制 | **只有 `VP[0]` 可作谓词**；`VP[1]` 供比较链的第二个目标与 `V_CNDMASK` 使用，**v1 不可作谓词**；`VP[2..7]` 的编码值保留但**无架构状态** |

> **⇒ 为什么用 opcode 变体而不是谓词字段**：64-bit `VOP3` 已**恰好装满**（11+32+21），没有余位；若强加 3-bit 谓词字段，`VOP3` 必须升到 80-bit（= 全部向量代码 +25% 取指带宽）。**用 64 项 opcode 换 3 bit 字段**是明显划算的交换。
> **⇒ 演进路径**：扩 `VP[2..7]` = **扩架构状态 + 占用更多比较类 opcode 序号**，**无需 EXT、无需改编码布局**（`VP` 索引字段本就保留 3 bit）；§3.5 的 `EXT` 前缀**仅在 opcode 空间耗尽时启用**。
> **⇒ 已记录的代价**：谓词空间只有 64 项/类 ⇒ **不是每条向量指令都有 `P` 变体**；无 `P` 变体的指令需要谓词化时，编译器必须降级为分支 + `JOIN`（性能代价，正确性无影响）。

> **⇒ 规范语句 S-PRED-1**：`VP` 只能由向量比较类写入；`SALU` 不得读写 `VP`；`VALU` 不得写 `SCC`。**跨域谓词写 = ISA 非法。**

### 1.4 发散与汇合

| 项 | 规范 |
|---|---|
| 发散表示 | 硬件维护 **per-warp 发散栈**；条件分支按 `EXEC ∧ cond` 分裂为两条路径，`EXEC` 随之更新 |
| **汇合点** | **编译器显式标注**：在汇合点插入 `SOPP.JOIN`（1 条 48-bit 指令，**无寄存器操作数**；`imm16` 携带 join-id） |
| 汇合语义 | `JOIN` 从栈顶弹出到最近的**同一 join-id** 条目，并恢复其 `EXEC`；**join-id 由 `JOIN` 的 imm16 字段给出**（编译器分配） |
| 栈空 | `JOIN` 遇到空栈 = **未定义行为**（编译器必须保证配对） |
| 嵌套 | 支持任意嵌套，深度上限为实现定义（≥ 8） |
| **发散下的程序顺序** | **warp 每拍发射 1 条指令**。发散区两侧的指令**串行发射**（先走一侧，再走另一侧），**两侧都会发射** ⇒ 动态指令序列 = 静态序列中该 warp 实际走过的部分 |
| **被跳过路径** | **仅 warp-uniform 分支的未取侧不发射** ⇒ 该侧指令携带的 `stall` **永不发生** ⇒ **不得依赖未取侧的指令承载任何 `stall` 义务**（见 §4.2 S-DEP-2c） |
| **warp-uniform 判定** | 编译器**不必**在编译期证明分支 uniform ⇒ **规范要求义务的承载指令位置对 uniform/divergent 都安全**（即位于「所有到达消费者的路径都必经」的支配点） |

> **⇒ 为什么不用 post-dominator 自动汇合**：PTX-EMU 用 CFG post-dominator 计算汇合点（39 号 §1.4），那是**解释器**的做法；硬件做 post-dominator 需要 CFG 信息 ⇒ 显式 `JOIN` 把这段逻辑交给编译器，**硬件只需一个栈**。这是 ISA 层的取舍，写入规范以免实现端各自发明。

## 2. 架构寄存器

### 2.1 数量与字段宽度（**编码相关 ⇒ 冻结**）

| 文件 | 架构数量 | 索引字段 | 分配粒度 | 对齐约束 |
|---|:---:|:---:|:---:|---|
| `SGPR` | **128** = **124 可分配 + 4 保留** | **7 bit** | 4 dword | 64-bit 值所在寄存器号**必须为偶数** |
| `VGPR` | **256** | **8 bit** | 4 dword | 同上 |
| `AccVGPR` | **256** | 8 bit（仅矩阵类指令） | 8 dword | 同上 |
| `VP` | **2**（v2 可扩至 8） | **3 bit**（仅 opcode 变体，无字段；`VP[2..7]` 在 v1 为保留编码值） | — | — |

### 2.2 SGPR 保留集（**4 个，逐项给理由**）

| 索引 | 名称 | 理由 |
|:---:|---|---|
| `s0` | `EXEC` | 逐 lane 执行掩码 |
| `s1` | `STATUS` | 舍入模式 / 异常使能等全局位（v1 只定义保留位，语义在 B-1 补） |
| `s2` | `M0` | 访存修饰符（cache 策略 / 描述符） |
| `s3` | `SCRATCH_BASE` | 每 wave 私有栈基址（local 空间） |

> **⇒ 规范语句 S-REG-1**：`s0..s3` **不得**作为普通数据寄存器分配；编译器可分配范围为 **`s4..s127`（124 个）**。
> **⇒ 规范语句 S-REG-1a（保留寄存器的读写权限）**：`s0..s3` **可作为普通源操作数被读**（如把 `EXEC` 读出保存），但**写权限受限**：`EXEC` 只能由 `SOPP.WREXEC` / `SOPP.SAVEEXEC` / 发散栈写；`STATUS` / `M0` / `SCRATCH_BASE` 只能由 `SOPP` 的 `SYS` 子空间指令写。**普通 `SOP1/SOP2/SOPK` 以 `s0..s3` 为目的寄存器 = ISA 非法。**
> **⇒ 不做的事**（显式记录，防止日后重提）：不采用 CDNA 的 `XNACK` / `TTMP` / `FLAT_SCRATCH`；**不提供内联常量块**（`SGPR[128..255]`）—— 所有常量走立即数字段，代价见 38 号 §3.1.1c。

### 2.3 每指令寄存器源上限

| 域 | VGPR 源 | SGPR 源 | 立即数 |
|---|:---:|:---:|:---:|
| 标量（`SOP*`） | **0**（不得寻址） | **≤ 2** | 1（`SOPK`） |
| 向量（`VOP*`） | ≤ 3 | **≤ 2** | 1 |

> **⇒ 规范语句 S-REG-2**：`SALU` 的源**只能**是 SGPR 或立即数；**不得寻址 VGPR / `AccVGPR` / `VP`**（X-D1）。
> **⇒ 规范语句 S-REG-3**：**每指令 SGPR 源 ≤ 2**（依据 SGPR 读端口数，X-D4）。

## 3. 指令编码

### 3.1 总则

| 项 | 规范 |
|---|---|
| 长度 | **48 bit 或 64 bit**（16-bit 粒度 ⇒ 二者都是 3 / 4 个 16-bit 音节） |
| 字节序 | 小端；音节内按位编号 **bit 0 = 指令首 bit** |
| 长度判定 | **由 `fmt` 唯一决定**（§3.2）；**唯一例外 = `EXT` 前缀**（`fmt=SOPP` 且 `op=0x7F` ⇒ 固定 64-bit，§3.5）。判定只需 **2 字节前瞻**（`fmt` 在 bit[2:0]、`op` 在 bit[10:3]，均落于首音节） |
| 对齐 | 指令起点 **2 字节对齐**；无更强要求 |
| 取指窗 | **16 字节**；指令**允许跨窗**，解码器持 1 条 carry-over |
| 分支目标粒度 | **2 字节** |

### 3.2 格式类（`fmt`）与长度

| `fmt` | 类 | 域 | 源数 | 长度 | 备注 |
|:---:|---|:---:|:---:|:---:|---|
| `000` | `SOP1` | 标量 | 1 | **48** | 1 源 + dst |
| `001` | `SOP2` | 标量 | 2 | **48** | 2 源 + dst（标量主力） |
| `010` | `SOPC` | 标量 | 2 | **48** | 比较 → `SCC` |
| `011` | `SOPK` | 标量 | 1 | **64** | 1 源 + **imm16** |
| `100` | `SOPP` | 标量 | 0 | **48** | 控制流 / `JOIN` / 系统（`SYS` 归此） |
| `101` | `VOP1` | 向量 | 1 | **48** | 1 源 + dst |
| `110` | `VOP2` | 向量 | 2 | **64** | 2 源 + dst；**`LSU` 归此**（opcode 子范围） |
| `111` | `VOP3` | 向量 | 3 | **64** | 3 源 + dst（向量主力） |

> **⇒ 规范语句 S-ENC-1**：`fmt` 恒位于**指令 bit[2:0]**、`op` 于 bit[10:3] ⇒ **长度判定只需 2 字节前瞻**（`EXT` 例外见 §3.1）。
> **⇒ 规范语句 S-ENC-2**：`fmt` 空间**已全部占用（8/8）** ⇒ 未来新格式类必须走 §3.5 的扩展机制。

### 3.3 位布局（**逐形态冻结**）

**48-bit（`SOP1/SOP2/SOPC/SOPP/VOP1`）**

| 形态 | `[2:0]` | `[10:3]` | `[11..]` 操作数区 | 控制块 |
|---|---|---|---|---|
| `SOP1` | `000` | op (8) | `s0[17:11]` · `dst[24:18]` · `RSV[31:25]` | `ctrl16[47:32]` |
| `SOP2` | `001` | op (8) | `s0[17:11]` · `s1[24:18]` · `dst[31:25]` | `ctrl16[47:32]` |
| `SOPC` | `010` | op (8) | `s0[17:11]` · `s1[24:18]` · `RSV[31:25]` | `ctrl16[47:32]` |
| `SOPP` | `100` | op (8) | `imm16[26:11]` | `ctrl16[42:27]` · `RSV[47:43]` |
| `VOP1` | `101` | op (8) | `src0[18:11]` · `dst[26:19]` | `ctrl21[47:27]` |

**64-bit（`SOPK/VOP2/VOP3`）**

| 形态 | `[2:0]` | `[10:3]` | `[11..]` 操作数区 | 控制块 | 剩余 |
|---|---|---|---|---|---|
| `SOPK` | `011` | op (8) | `s0[17:11]` · `dst[24:18]` · `imm16[40:25]` | `ctrl16[56:41]` | `RSV[63:57]`（`SMEM` 用作 `SOFFSET[63:57]`） |
| `VOP2` | `110` | op (8) | `src0[18:11]` · `src1[26:19]` · `dst[34:27]` | `ctrl21[55:35]` | **`imm8[63:56]`** / `RSV`（`LSU` 用作 cache 策略） |
| `VOP3` | `111` | op (8) | `src0[18:11]` · `src1[26:19]` · `src2[34:27]` · `dst[42:35]` | `ctrl21[63:43]` | — |

> **⇒ 校验（机械）**：48-bit 各形态 ≤ 48；64-bit 各形态 ≤ 64。**`SOP2` 与 `VOP1` 恰为 48；`VOP3` 恰为 64**（36 号 §4.5.2）。
> **⇒ 规范语句 S-ENC-3**：`VOP2` 的 `[63:56]` 在 ALU 类为 **`imm8`**、在 `LSU` 类为 **cache 策略**；二者互斥，由 opcode 范围决定。

### 3.4 控制块（**Q-10 / Q-11：按域裁剪，唯一口径**）

**向量域（21 bit）**

| 字段 | 位 | 语义 |
|---|:---:|---|
| `stall` | `[3:0]` | 本 warp 在发射**下一条**指令前必须等待的发射机会数（0 = 不等待）。**同时承担 late-addr 类的 WAR 保护**（§4.5） |
| `sb_id` | `[6:4]` | 本指令作为**可变延迟生产者**时占用的 SB 槽号 |
| `wait_mask` | `[14:7]` | 发射前须等待归零的 SB 槽集合（1 bit/槽，**只覆盖 `SB[8]`**） |
| `reuse_flags` | `[17:15]` | 逐 op_pos 的复用提示（**纯提示**，由**架构保证 A-1**〔36 号 E-9〕兜底） |
| `budget_hint` | `[19:18]` | 该源将被消费的次数档位（**纯提示**） |
| `yield` | `[20]` | 建议让出本拍 |

**标量域（16 bit）**

| 字段 | 位 | 语义 |
|---|:---:|---|
| `stall` | `[3:0]` | 同上 |
| `sb_id` | `[6:4]` | 同上 |
| `wait_mask` | `[14:7]` | 同上 |
| `yield` | `[15]` | 同上 |

> **⇒ 规范语句 S-CTRL-1**：**不存在 WAR 字段、不存在 `width_hint` 字段、不存在 `late_addr` 字段。** 前者的语义由 `stall` 承担（§4.5）；后两者由 **opcode 变体**承载。
> **⇒ 规范语句 S-CTRL-2**：标量域**无** `reuse_flags` / `budget_hint` —— 其语义仅对 VGPR 定义（MCOS 槽键为 `(bank, op_pos)`）。

### 3.5 opcode 空间与演进

**统一分段规则（`op[7:6]` 为变体类，`op[5:0]` 为类内序号）**：

| `op[7:6]` | 段 | 项数 | 含义 |
|:---:|---|:---:|---|
| `00` / `01` | **普通** | 64 + 64 = **128** | 无谓词（仅受 `EXEC` 约束） |
| `10` | **`P` 变体** | **64** | **隐含谓词 `VP[0]`**（§1.3） |
| `11` | **专用子空间** | **64** | 按 `fmt` 分配：`VOP2` = **`LSU`**（`LD`/`ST`/原子）；`SOPP` = **`SYS`**（`bar.sync`/`dep.wait`/`mem.wait`/`mem.fence`/`WREXEC`/`SAVEEXEC`）；其余 `fmt` 保留 |

| 项 | 规范 |
|---|---|
| 类内 opcode | `op[7:0]` = **256 项 / 类**（上表分配） |
| **`late-addr` 的承载** | **`LSU` 段内的独立序号**（`LD.LATE` / `ST.LATE`）⇒ **不占控制位、不占 `P` 段** |
| `width_hint` 的承载 | 窄值算术（`.f16x2` / 打包类）用**独立序号** |
| `JOIN` 的承载 | `SOPP` 普通段（`imm16` = join-id，§1.4） |
| 空间耗尽的扩展机制 | 启用 `SOPP` 的保留序号 `0x7F` 作为 **`EXT` 前缀**（见下） |

**`EXT` 扩展形态（v1 只定义骨架，不实现）**

```
EXT 形态（64 bit）：
  [2:0]      = 100          (SOPP 的 fmt，SOPP 只在 EXT 前缀里作载体)
  [10:3]     = 0x7F         (EXT 标识)
  [14:12]    = ext_class    (3 bit  ⇒ 8 个扩展类)
  [17:15]    = ext_op       (3 bit  ⇒ 每类 8 个操作)
  [31:18]    = 保留 (14 bit)
  [63:32]    = 扩展载荷 32 bit   ← 16-bit 扩展音节 + 可选第二个
  ⇒ 控制块沿用域对应的 21/16 bit（由 ext_class 的高位决定标量/向量）
  ⚠ 位段互不重叠：ext_class 占 [14:12]、ext_op 占 [17:15]、保留 [31:18]
```

| 项 | 结论 |
|---|---|
| 扩展类数 | **8 个**（3 bit）× 每类 8 个操作（3 bit） |
| 载荷 | **32 bit** —— 足够承载 v2 的**矩阵类操作数**（`AccVGPR` 索引 8 bit × 最多 2 个 = 16 bit，其余留给控制位扩展） |
| 控制块 | 沿用向量 21 / 标量 16 bit（不新增字段） |
| **承载力结论** | **够用但吃紧**：矩阵类若需 3 个 `AccVGPR` 源 + 1 个 dst，32 bit 载荷不够 ⇒ **矩阵类在 v2 需要 128-bit 形态**（`EXT` + 2 个扩展音节） |
| **⇒ 因此** | **「v2 走 `EXT`」是一条 TBD，不是承诺**（见 §8 T-10）：矩阵类形态在 v2 启动前必须单独裁决 |

> **⇒ 规范语句 S-OPC-1**：**`late-addr` 必须在 v1 的 opcode 空间内预留位置**，即使 Q-9 的实测判据最终选择"暂缓实现"（36 号 §7.2）—— 预留是编码决策，实测是性能决策，二者不得互相等待。

## 4. 依赖层规范

### 4.1 不变式（**全部可机械检查**）

| # | 不变式 | 内容 |
|:---:|---|---|
| **D-1** | 源锁存窗口 ≤ 写可见延迟 | 对每个**非豁免**指令类 `c`：`D_c ≤ L_w,min` |
| **D-1′** | WAR 可表达性 | 对每个**豁免**指令类 `c`：`D_c − L_w,min ≤ 15`（= `stall` 字段上界） |
| **D-2** | 依赖状态 ∝ 在飞生产者数 | 每 warp 可区分的在飞可变延迟生产者 **≤ 8**（`SB[8]`，架构契约） |
| **D-3** | 提示不影响可观察语义 | `reuse_flags` / `budget_hint` 的任意取值都不改变结果 |

> **⇒ 规范语句 S-DEP-0（`L_w,c` 的方向性，v1 的关键紧边界；critic BLOCKER-2 修正）**：
> - **固定延迟类（由 `stall` 保护）**：`L_w,c` 是**精确的架构承诺值** —— 目的寄存器**恰在** `issue + L_w,c` 可见。**不得更早**（更早 ⇒ §4.5 的 WAR 紧边界被击穿）；**不得更晚**（更晚 ⇒ `stall` 保护的 RAW 读到陈旧值）。
> - **可变延迟类（由 `SB` 槽保护）**：可见时刻**不得早于** `issue + L_w,c`；**更晚无妨**（消费方等的是槽归零，不是固定拍数）。
> - **全局下界**：**任何类的 `L_w,c ≥ L_w,min = 4`**。
>
> **为什么必须"精确"而不是单边约束（本条曾被写反的地方）**：
>
> | 方向 | 依赖它的是 | 若违反 |
> |---|---|---|
> | **写者可见不得更早** | §4.5 的 WAR（标准类 `D_mem = 4` 与 `L_w,min = 4` **取等**；late-addr 类 `D_mem = 11` 在 `d = 8` 时有 **1 拍余量**） | 写者提前可见 ⇒ **WAR 事故** |
> | **生产者可见不得更晚** | `stall` 保护的 RAW（消费者在 `t_p + L_w` 读） | 生产者延后可见 ⇒ **RAW 读到陈旧值** |
>
> ⇒ **两个方向都要 ⇒ 只能是精确值。**
> **推论**：某域实测更快（例：标量 ALU 3 拍）**不得**下调声明值 —— **硬件可以更快，但架构可见时刻仍须落在 `issue + 4`**（实现须插入延迟对齐，或把该类的 `D_c` 同步收紧以维持 D-1）。
> **⇒ 33/34 号基于 `L = 4` 的 IPC 结论因此是「架构承诺下的结论」，不是「希望硬件恰好如此」的假设。**
> **⇒ 规范语句 S-DEP-1**：**两条不变式都必须由 §4.6 的延迟表逐一核对**，核对结果记入规范附录。任一类不满足 ⇒ 该类**不得进入 v1 指令集**。

### 4.2 `stall` 语义

| 项 | 规范 |
|---|---|
| 计数单位 | **本 warp 的发射机会**（不是 wall-clock 周期） |
| 递减 | 每拍若本 warp 是发射候选则递减；warp 未当选时不递减 |
| **生效点** | **本指令发射后**开始倒数；归零后**下一条指令**才能发射 ⇒ ⚠ **`stall` 推迟的是「它自己之后」的指令，不是它自己** |
| **落点约定** | **延迟由「gap 内的生产者」携带** —— 携带者与被保护者之间的**程序序间隔**被撑开（与 NVIDIA 同构：生产者携带 `延迟 = L_w − 间隔数`） |
| 上界 | 15 |
| 可表达性规则 | `L_w,c ≤ 15` 的定长类走 `stall`；`L_w,c > 15` 的类**必须**声明为可变延迟类（走 `SB`）或扩展 `stall` 位宽（36 号 E-14） |

> **⇒ 规范语句 S-DEP-2**：`stall` 按**发射机会**计数。这使"warp 被换出"只可能**增加**实际经过时间 ⇒ 编译器按发射距离做的静态推理**保守成立**（36 号 §4.1.6）。

> **⇒ 规范语句 S-DEP-2a（落点语义，critic BLOCKER-1 修正）**：**凡需要「推迟某条指令」的场合，延迟必须落在「被推迟者之前」的 gap 内**（优先落在 gap 内的生产者上）。
> **⇒ 禁止写法（反例）**：在**写者 `W`** 上置 `stall` 以保护 `W` 自己的写可见时刻 —— `W` 上的 `stall` 推迟的是 `W` 的**后继**，对 `W` 自身**保护恒为 0**。
> **⇒ 规范语句 S-DEP-2c（最小间隔义务的路径鲁棒性，oracle 审查追加；措辞经复审精确化）**：一条 `stall` 义务（RAW/WAW/WAR）的**承载指令必须位于「gap `(P, C]` 内、且在从生产者 P 到消费者 C 的每条路径上都会被发射」的位置** —— 即它是 **gap 内支配 C 的公共支配点**上的指令。
> ⚠ **两个限定缺一不可**：① **必须在 gap `(P, C]` 内**（若支配点位于 P **之前**，它的 `stall` 会同步推迟 P 与 C ⇒ gap 不变 ⇒ **保护恒为 0**）；② **必须支配 C**（在所有到达 C 的路径上发射）。
> **理由**：`stall` 是「发射后推迟后继」的**最小间隔**担保。若承载指令位于某条**可能不被发射**的路径上（典型：warp-uniform 分支的未取侧，§1.4），则该侧不发射 ⇒ **它的 `stall` 永不发生** ⇒ 消费者**提前发射** ⇒ 读到**陈旧值** ⇒ **程序结果错误**。
> **⚠ A-1 不救此错**：A-1 保证「槽交付值 ≡ RF 当前值」，但提前发射时 RF 当前值**本身就是旧的** ⇒ A-1 成立而语义仍错。
> **⇒ 编译器的两条合法出路**：
> ① **把义务放在公共支配点上**（推荐）：如分支指令本身、`JOIN` 之后、或更早的公共祖先 —— 该位置**对 uniform / divergent 都安全**；
> ② **插入一条无条件发射的指令**作为承载（调度屏障 / `dep.wait`），再把义务交给它。
> **⇒ 若二者都不可行**（无公共支配点且不允许插指令）：**该依赖不得用 `stall` 表达**，必须改由 **SB 槽 + `wait_mask`**（硬件机制）承担。
> **⇒ 义务量的多路径取值**：不同路径的指令数不同 ⇒ 所需 `stall` 不同 ⇒ 编译器必须取**所有路径的最大值**（保守）；承载指令的位置按 ① 选在支配点上。
> **⇒ WAR 义务的对偶形式**：WAR 义务的「P→C」应读作「**读者 R → 写者 W**」。**该形式由 W-2（R/W 同基本块）蕴含满足**：R 发射 ⟺ 该块发射 ⟹ W 发射 ⇒ `R` 的 `stall` 必然生效；若整块不发射 ⇒ W 也不写该寄存器 ⇒ 无事故。**lane 级掩码不改变此结论**（同块 ⇒ 同侧 ⇒ 同 `EXEC` 掩码）。
> **⇒ 机械可判定**：承载指令是否在 gap `(P,C]` 内且支配 C，是**编译期 CFG 计算**（支配树），可在 M-1 中机械核对（附录 B 检查 16）。

> **⇒ 规范语句 S-DEP-2b（两类 `stall` 义务的合成）**：**同一条指令可能同时背负两类 `stall` 义务** —— ① **M-1 的 RAW 义务**（保护生产者→消费者的 gap）；② §4.5 的 **WAR** 义务（保护 late-addr 读者→写者的 gap）。
> **合成规则（顺序处理 + 取 max 累积）**：编译器**顺序**处理义务；处理义务 `o`（gap `G_o`，门槛 `T_o`，承载指令 `c(o)`）时
> `need(o) = T_o − Σ_{i ∈ G_o, i ≠ c(o)} stall(i)`（用**已分配**的 `stall` 值），`stall(c(o)) = max( stall(c(o)), need(o) )`。
> **可表达性**：RAW 义务 ≤ 15（E-14：`L_w ≤ 15`）、WAR 义务 ≤ 15（D-1′：`D_c − L_w,min ≤ 15`）⇒ **`max ≤ 15` 恒可表达**，合成不会溢出 4-bit 字段。
> ⚠ **注意方向**：`stall` 是「推迟后继」，因此**落在 gap 内靠前位置的指令，其 `stall` 会同时推迟它后面的所有 gap 指令** ⇒ **取 max 而非求和**（同一 `stall` 对它参与的每个 gap 贡献相同）。
> **推导与可执行锚例见 36 号 §4.1.6「两类 `stall` 义务的合成」（含可复现脚本）。**

### 4.3 SB 槽语义

| 项 | 规范 |
|---|---|
| 数量 | **8**（per-warp，标量/向量**共享同一池**） |
| 计数器宽度 | **6 bit**（0..63） |
| 递增 | 生产者 **issue 后一拍 +1** |
| 递减 | 生产者 **writeback 时 −1**（每次写回 −1） |
| 消费者等待 | `wait_mask` 中置位的槽，**全部归零**后才可发射 |
| 语义 | **并集等待**（不表达"等第 k 个"，只表达"等这些槽都空"） |

> **⇒ 规范语句 S-DEP-3（E-7a 架构契约）**：**每 warp 可区分的在飞可变延迟生产者 ≤ 8。** 冻结后**不得靠加深硬件队列突破** —— 否则编译器可产生 > 8 个在飞生产者而无法表达。
> **⇒ 规范语句 S-DEP-4（E-7b 槽耗尽规则）**：编译器在超过 8 个在飞可变延迟生产者时**必须**二选一：① 合并到同一槽（同 `wait_mask` 位 ⇒ 并集等待）；② 插 `dep.wait` 排空。**两种退路都不得死锁**（生产者必然完成 ⇒ 计数必然归零）。

### 4.4 延迟表 schema（E-14）

| 键 | 值域 |
|---|---|
| 指令类 | `fmt` × opcode 范围（如 `VOP3.FMA_F32`） |
| **域** | 标量 / 向量 |
| `D_c` | 源锁存窗口（1..63） |
| `L_w,c` | 目的可见延迟（1..63） |
| 是否豁免 D-1 | 是（late-addr 类）/ 否 |

> **⇒ 规范语句 S-DEP-5**：查表**必须按域分别给出** —— 标量域的 `L`/`L_w`/`D_c` **不得**沿用向量域数值（38 号 I-3：AMD 不公开 SALU 延迟，须自测）。

### 4.5 late-addr 类的 WAR（**Q-11**）

> **机制**：late-addr 读者 `R` 在 `t(R) + D_mem`（`D_mem = 11`）才锁存源；写其源寄存器的指令 `W` **必须**满足 `t(W) + L_w,min > t(R) + D_mem` ⇒ **由 gap 内的 `stall` 撑开间隔**（推导见 36 号 §4.1.6）。

> **记号**：`slot(k)` = 指令在 warp 指令流中的序号；`A(k) = Σ_{i<k} stall(i)`；`t(k) = slot(k) + A(k)`。

| 情形 | 规范要求 |
|---|---|
| **条件** | **`d + Σ_{R ≤ i < W} stall(i) ≥ 8`**，其中 `d = slot(W) − slot(R)` |
| **落点** | **gap `[R, W)` 内**，优先 **`R` 自身**（如 `d = 1` ⇒ `R.stall ≥ 7`）。⚠ **不是 `W`** —— `W` 上的 `stall` 推迟的是 `W` 的后继（36 号 §4.1.6） |
| `d ≥ 8` 且 gap 内无其他 stall | 无需动作 |
| `d < 8` | gap 内累计 `stall` **必须 ≥ `8 − d`** |
| `d` 不可静态确定，或 `R`/`W` 不在同一基本块 | **编译器不得标注 late-addr**（回退为普通访存）—— **实例级义务 W-1 / W-2** |

> **⇒ 规范语句 S-DEP-6a（实例级义务，不可只靠逐类检查）**：**对每个 late-addr 读者 `R` 及其每个后继写者 `W`，编译器必须能静态确定 `d` 与 gap 累计 `stall`，并验证 `d + Σ ≥ 8`；否则撤销 `.LATE` 标注。**
> **⇒ 规范语句 S-DEP-6b（`W` 是访存指令时更宽松）**：若 `W` 本身走 SB 槽（写可见远晚于 `issue + 4`），条件自动更宽松 ⇒ 仍按最坏 `L_w = 4` 计算即安全（**实例级义务 W-3**）。

> **⇒ 规范语句 S-DEP-6**：**ISA 不提供 WAR 计数器 / WAR scoreboard / WAR 槽位。** WAR 完全由 `stall` + D-1/D-1′ 覆盖。**这是一条冻结决策**（36 号 Q-11）—— 实现端不得"顺手加一个 WAR 计数器"，那会与 `stall` 语义重叠并产生双重阻塞。

### 4.6 v1 延迟常量（**数值 TBD 的见 §8**）

| 类 | `D_c` | `L_w,c` | 豁免 D-1 | 依据 |
|---|:---:|:---:|:---:|---|
| 向量 ALU（定长） | **3** | **4** | 否 | 36 号 Q-4/Q-6 |
| 标量 ALU（定长） | **TBD**（≤ 4） | **4**（**声明值**，§4.1 S-DEP-0 —— 精确承诺，不得更早也不得更晚） | 否 | 38 号 I-3（`D` 须自测；`L_w` 固定声明 4） |

| **late-addr 访存** | **11** | 走 SB | **是** | 36 号 Q-9 |
| 矩阵类（v2） | 按形状分档 | 32..64 ⇒ **必须走 SB** | 否 | 37 号 §3.2（`L_w > 15`） |

> **⇒ 规范语句 S-DEP-7**：表中 **`TBD` 项不得以"参照 CDNA"填补** —— AMD 不公开 SALU / SMEM 延迟（38 号 X-2）。B-1 之前必须给出自测值或给出显式保守上界。

### 4.7 依赖相关指令

## 5. 内存模型（v1 最小规范）

### 5.1 scope 分级

| 级别 | v1 | 含义 |
|---|:---:|---|
| `CTA` | ⬜ 推迟 | 仅 v1.1 |
| **`GPU`** | ✅ **v1 唯一实现级别** | 全 device 可见序 |
| `SYSTEM` | ❌ 不做 | 无 host 一致性需求 |

> **⇒ 规范语句 S-MEM-1**：v1 **只实现 `GPU` scope**；`CTA` / `SYSTEM` 的修饰符编码位**预留但语义未定义**，使用即未定义行为。

### 5.2 等待状态（**必须与寄存器依赖状态分离**）

| 指令 | 等待的是什么 | 状态归属 |
|---|---|---|
| `dep.wait` | `SB[8]` 计数器归零 | **寄存器依赖状态** |
| `mem.wait` | **per-warp 在飞访存计数归零** | **内存可见性状态** |
| `mem.fence` | 同上 + 保证此前访存对其后访存**有序** | 同上 |

> **⇒ 规范语句 S-MEM-2（落实 35 号 R-3）**：**内存序不得复用寄存器槽位** —— `mem.wait` 与 `dep.wait` 状态**物理分离**，编码上也不得互相替代。
> **⇒ 规范语句 S-MEM-3**：`mem.fence` 的等待对象 = **本 warp 在飞访存计数归零**（v1 取"排空"语义，不做部分 fence）。

### 5.3 验证约束（**规范级，不是建议**）

> **⇒ 规范语句 S-MEM-4**：**内存序语义不得声明"由 PTX-EMU 差分覆盖"** —— PTX-EMU 的 `membar`/`fence` 是 no-op（39 号 G-6），只能验证到"功能路径不崩"。内存序正确性**必须**由自有测试套件（LLVM IR 层 golden 或形式化用例）验证。

## 6. 双域规则（**规范语句化，去论证**）

| # | 规则 |
|:---:|---|
| **X-D1** | `SALU` 的源**只能**是 SGPR 或立即数；**不得寻址** VGPR / `AccVGPR` / `VP` / LDS |
| **X-D2** | `VALU` 的源**可以**是 VGPR / SGPR / 立即数；读 SGPR **不额外占发射槽** |
| **X-D3** | **`SGPR ← VGPR` 非法。** 必须经 `V_READFIRSTLANE_B32`（计 1 个 VALU 发射槽 + 其延迟 + 一条 `stall`/`wait`） |
| **X-D4** | **每指令 SGPR 源 ≤ 2**（读端口约束） |
| **X-D5** | `VP` 只能由向量比较类写入，`SALU` 不得读写 `VP`（替代 38 号 v1.0 的 VCC-in-SGPR 规则） |

> **⇒ 规范语句 S-DUAL-1**：X-D1 / X-D3 的违反是**编译期非法**（汇编器必须拒绝），不是运行时未定义行为。
