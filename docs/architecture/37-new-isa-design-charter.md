## 0. TL;DR

> **裁决（Q-8）**：**新 ISA 是本仓 GPGPU 的唯一 ISA**；PTX / CDNA3 / SASS **降级为调研与参考**（行为基线、延迟分档、先例），**不再是实现目标**。

| # | 结论 | 章节 |
|---|------|------|
| **①** | **"取代"的范围必须分层**：取代的是**指令集与前端**，**不是**行为基线、**不是** timing 宿主范式、**不是** 双 vendor 硬件建模 | §2 |
| **②** | **最大依赖风险 = 编译器**：依赖层方案是**编译器驱动**的（stall count / 槽分配 / 复用提示）⇒ **没有能产出这些元数据的编译器，整个设计无法落地** | §4 |
| **③** | **四个连锁后果**：ADR-SOC-15 Phase C 被取代；13 号 CDNA-EMU 选型作废；11 号双轨前端收敛为单一前端；12 号校准基线的**对标对象**改为 NVIDIA/AMD 实测延迟表 | §5 |
| **④** | **ISA 范围建议分 3 层**：v1 = 标量/向量 ALU + 访存 + 控制；v2 = 张量/矩阵；v3 = 变长延迟与推测类 | §3 |
| **⑤** | **不变的锚点**：33 号的 `W = 2` / `d = 1` / IPC 结论与 36 号的不变式 **均不因换 ISA 而改变**（它们是**微架构**结论，不是 ISA 结论） | §6 |

## 1. 为什么需要这份总纲

Q-8 的裁决把新 ISA 从"**依赖层的一个设计方案**"提升为"**本仓 GPGPU 的唯一指令集**"。这带来三类必须显式回答的问题：

| 类别 | 问题 | 本文回答位置 |
|------|------|------------|
| **边界** | 新 ISA 取代什么？不取代什么？ | §2 |
| **范围** | 第一版包含哪些指令类？ | §3 |
| **依赖与顺序** | 新 ISA 依赖谁？被谁依赖？哪些既有决策被取代？ | §4–§6 |

## 2. 「取代」的范围（**必须分层，否则会误伤**）

### 2.1 被取代的

| 对象 | 原定位 | 新定位 |
|------|--------|--------|
| **PTX**（`ptx` 前端） | 虚拟 ISA / 阶段 A-D 的起跑 ISA | **仅参考**：语义基线、PTX 生态与算子覆盖面的调研来源 |
| **CDNA3 / GFX942**（`cdna3` 前端） | 阶段 C 的**物理 ISA**目标 | **仅参考**：真实硬件 ISA 的设计先例（MFMA 分档、waitcnt 语义、DELAY_ALU） |
| **SASS** | （Oracle 评估：不推荐为第一目标，无公开手册） | **仅参考**：延迟分档表、控制位布局、RFC 语义 |
| **ADR-SOC-15 Phase C**（CDNA 引擎接入） | 路线图的关键路径 | **被取代** ⇒ 需 superseding ADR |
| **13 号 CDNA-EMU 选型** | 阶段 C 启动前的必做调研 | **作废**（不再需要选 CDNA-EMU；可转为"参考其 ISA 语义"的调研） |

### 2.2 **不被取代**的（⚠ 关键：混淆这两栏会导致误删）

| 对象 | 为什么保留 |
|------|-----------|
| **ISA 中立 timing 宿主**（11 号 §11.1） | **范式仍成立且更重要**：新 ISA 前端 = 我们的解码器，产出 `InstrDescriptor`；timing 宿主不变 ⇒ **SoC 建模与 ISA 解耦的价值不变** |
| **`InstrDescriptor` 契约**（11 号 §11.2.1 / HSK-9） | 新 ISA 的依赖控制块（**向量 21 bit / 标量 16 bit**，36 号 Q-10）**随描述符走**；跨仓 size 约束（128 B）**依旧生效** |
| **NVIDIA / AMD 作为硬件建模对象** | 本仓 SoC 仍模拟 **NVIDIA-like / AMD-like** 的机器；实测延迟表是**校准基线** |
| **ADR-SOC-09 双 vendor 战略** | **降级但不废止**：从"要支持两个 vendor 的 ISA"变为"**用两个 vendor 的实测数据做行为基线**" |
| **12 号校准基线的方法论** | 仍需要"模型 vs 实测"的校准闭环；**只是对标对象从 CDNA 硬件换成 NVIDIA/AMD 的公开实测延迟表** |
| **33 号 OSF 的全部微架构结论** | `W = 2` / `d = 1` / IPC 目标 / MCOS 语义 —— **这些是微架构结论，与 ISA 无关**；⚠ **但均为【向量域】结论**（引入标量域后需分域重算，见 [`38-…`](./38-new-isa-dual-domain-structure.md) §5） |
| **`isa_type` 配置机制** | 从"多值可选"收敛为"**单值 + 回放模式**"（trace replay 用于回归，见 §3.4） |

### 2.3 一句话总结

> **取代的是"指令集与前端"，不是"硬件建模目标"，也不是"微架构结论"。**

## 3. ISA 范围建议（分 3 层，v1 最小可用）

### 3.1 v1 —— 最小可用指令集（**必须先能跑通依赖层**）

| 类别 | 内容 | 依赖层要求 |
|------|------|-----------|
| **标量 ALU** | **`SOP1/2/C/K/P`**（1–2 源，操作 **SGPR**）—— 借鉴 CDNA 的 `S_*` 风格（38 号 §3.3） | 定长 RAW/WAW ⇒ **编译器 stall count**；⚠ **SALU 不可寻址 VGPR/LDS**（38 号 X-D1）⇒ 编译器须做 **uniformity 分析** |
| **向量 ALU** | **`VOP1/2/C/3`**（1–3 源，操作 **VGPR** + **SGPR**）—— 借鉴 CDNA 的 `V_*` 风格 | 3 源为主 ⇒ `L = 3`、`L_w = 4`（36 号 Q-6）；**VALU 读 SGPR 合法且廉价**（38 号 X-D2） |
| 访存 | `LD` / `ST`（全局 / 共享 / 常量）、原子（`ATOM`） | 可变延迟 ⇒ **SB 槽**；`D_mem = 4`（标准）/ `11`（**late-addr** 类，Q-9） |
| 控制 | `BRA`（条件/无条件）、`BAR.SYNC`、`EXIT` | B registers + barrier mask |
| 依赖等待 | **`dep.wait`**（等 SB 槽归零）、**`mem.fence`**（内存序） | E-10 / E-11 |
| 谓词/掩码 | 谓词寄存器 + 向量掩码 | **编码与数量在 40 号 §1 执行模型章定义**（38 号 §3.1.1b 提案：标量 `SCC` 1 bit + 向量 `VP[2]` 逐 lane 掩码，**独立谓词文件**，索引 3 bit 保留）。⚠ **谓词 ALU 的 golden 验证走 LLVM IR 层，不走 PTX-EMU**（39 号 G-1） |

### 3.2 v2 —— 计算密集型

| 类别 | 内容 | 依赖层要求 |
|------|------|-----------|
| 矩阵/张量 | `MMA`（形状可变 ⇒ 延迟随 shape 变，**编译期已知**） | **延迟分档**（AMD MFMA 32/64 拍 的教训：分档要进 ISA 规范） |
| 扩展数学 | `MUFU` / `RCP` / `RSQ` / `SIN` / `COS`（**变长延迟**） | 走 **SB 槽**（可变延迟路径） |
| 原子与内存序增强 | 作用域原子、内存序谓词 | `mem.fence` 扩展 |

### 3.3 v3 —— 探索类（**不承诺**）

| 类别 | 内容 | 依赖层要求 |
|------|------|-----------|
| 变长延迟 ALU | 部分 ALU 引入变长延迟 | **突破 I2** ⇒ 需要 scoreboard ⇒ 面积爆炸 ⇒ **默认不做** |
| 推测供给 | 值预测 / 推测执行 | 33 号 §4.4 SOP（探索项） |

### 3.4 始终保留的"非 ISA"通道

| 通道 | 用途 |
|------|------|
| **trace replay 模式** | 用真实硬件的 trace（NVbit / 其他）回归 timing 模型 —— **不产生新 ISA 语义**，只做校准 |
| **无前端模式** | 单模块单元测试 |

## 4. 最大依赖风险：**编译器**

> ⚠ **这是本文最重要的一节。**

### 4.1 为什么它是硬依赖

36 号的依赖层方案是**编译器驱动**的（继承自 NVIDIA）：

| 编译器必须产出 | 若缺失的后果 |
|--------------|------------|
| **stall count**（定长 RAW/WAW 的等拍数） | **程序结果错误**（论文实测：设错 ⇒「the result of the program is incorrect」） |
| **SB 槽分配 + wait mask**（可变延迟依赖） | 读到陈旧值 / 假阻塞 |
| **槽分配**（编译器把不同依赖分到不同槽） | 槽耗尽 / 假阻塞 |
| **late-addr 标注**（Q-9） | 地址链 kernel 的 issue 端吞吐损失 |
| **复用提示 + budget hint + width hint** | **仅性能**（36 号 A-1/A-2 兜底）✅ 唯一"可失败"的一类 |

⇒ **前 4 项是"正确性元数据"，编译器错 = 程序错。**

### 4.2 这与 NVIDIA 的差别

NVIDIA 有 **ptxas**（NVCC 后端）十余年打磨；AMD 有 **LLVM AMDGPU 后端**。**我们没有。**

> ⇒ **新 ISA 项目必须包含"编译器后端"或至少"一个能产出正确依赖元数据的汇编器 + 调度 pass"**，否则：
> - ISA 规范再完善，也无法产生**正确的代码**；
> - 33 号的 OSF 机制（依赖编译器复用意识）与 36 号的依赖层（依赖编译器元数据）**全部落空**。

### 4.3 最小可行路径（建议）

| 方案 | 工作量 | 说明 |
|------|-------|------|
| **A. 只写汇编器 + 手工调度** | 小 | 只能验证**微架构**，不能验证"编译器能正确产出元数据" ⇒ **无法闭合 36 号的正确性论证** |
| **B. 汇编器 + 一个依赖元数据生成 pass** | 中 | pass 负责：算 stall count（**含 RAW/WAR 两类义务的 max 合成**，40 号 S-DEP-2b）、分槽、填 mask、**判 late-addr 且做 W-1/W-2 实例级验证**（不满足即撤销 `.LATE`）、填复用提示 ⇒ **可闭合正确性论证**（**具体算法 M-1..M-4 见 [`39-…`](./39-new-isa-compiler-backend.md) §6**） |
| **C. 完整编译器后端（LLVM 插件）** | 大 | 最完整，但启动成本高 |

> **建议 B → C**：先用 **B** 闭合正确性论证（这是 ISA 规范可信的前提），再评估 **C**。
> **前提**：需与本仓的 `InstrDescriptor` 契约、**依赖控制块布局（向量 21 bit / 标量 16 bit，36 号 §4.5.1）**（35 号 §6.1 的取字节方案据此调整）**同步冻结**。

## 6. 不因换 ISA 而改变的东西（**锚点**）

| 结论 | 出处 | 为什么不变 |
|------|------|-----------|
| `W = 2`（每 sub-core 每拍 2 次 warp 寄存器读） | 33 号 §3.1 | **微架构**结论（bank 数 × 读口数），与 ISA 无关 |
| `d = 1`（FU 占用 1 拍） | 33 号 §4.4.1b | 同上 |
| 3 源序列 IPC 0.667 → MCOS 后 1.000 | 33 号 §4.1.4b / 34 号 | 同上（依赖层不改变读次数与延迟） |
| MCOS 语义与 fail-safe 性质 | 33 号 §4.1.2 / §7.2 | 同上（且 36 号的 A-1/A-2 只是把它**提升为架构保证**） |
| 依赖层四层分离 | 35 号 §2 | 同上 |
| 读带宽 vs 依赖层的正交 | 33 号 / 34 号 | 依赖层只改"何时可读"，不改"读几次" |

> **⇒ 换 ISA 不需要重做 33/34 号的任何量化结论。**
