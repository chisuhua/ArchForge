## 0. TL;DR

> **一句话**：**新 ISA 不该"在 NV / AMD / 学术里三选一"，而该吸收三者的机制、回避三者共同的架构约束——并用"操作数供给层可按 tag 校验"这一新资产，把依赖层的正确性责任从编译器手里大幅收回。**

| # | 结论 | 章节 |
|---|------|------|
| **①** | **五家做法的机理可提炼为 4 条机制 + 3 条约束**；NV 靠"编译期已知"取胜、AMD 靠"硬件兜底"取胜、学术方案靠"通用"取胜——**三者不可直接拼接**，因为它们的**隐含前提互斥** | §3 |
| **②** | **推荐方案 E = 「NV 式紧凑控制位」+「一条新不变式」+「硬件 tag 兜底」** | §4 |
| **③** | **新不变式 D-1（源锁存窗口 ≤ 写可见延迟）⇒ WAR 类依赖被收缩到只剩「延迟地址访存」一小类**（v1.1 曾写"WAR 整类消失"——**过度**；Q-9：pointer-chasing 类地址源无法 4 拍内就绪）。**v1.3（Q-11）：这一小类也不需要 WAR 计数器/槽位** —— 该类的 WAR 由**写者已有的 stall count** 表达（`D_mem − L_w,min = 7 ≤ 15`）⇒ **Q-1 的 WAR 槽取消** | §4.1 / §4.1.6 |

## 1. 为什么新 ISA 的依赖层是"设计问题"

### 1.1 两种问题的区别

| | **建模问题**（35 号文档） | **设计问题**（本文） |
|---|---|---|
| 目标 | 复现既有硬件的**可观测行为** | 定义**新的可观测行为** |
| 约束 | **被实测锁死**（NV 就是 41 bit/warp + 6 SB + DEPBAR） | **自由**（可改编码、可改不变式、可改指令集） |
| 判据 | "哪种做法能解释实测数据" | "哪种做法能达成目标（面积 / 正确性保证 / 编译器负担 / 吞吐）" |
| 失败模式 | 精度不足（MAPE） | 设计缺陷（面积爆炸 / 正确性漏洞 / 编译器负担失控） |

> **关键**：新 ISA **不受"必须复现 NV"的约束**，因此可以采用**现有硬件因为成本约束而放弃的方案**——这是新 ISA 最大的设计自由度。

### 1.2 本仓已有的相关资产

| 资产 | 状态 | 对新 ISA 的意义 |
|------|------|---------------|
| **ISA 中立 timing 宿主** + `InstrDescriptor` 契约 | 已设计（[`11-…`](./11-cdna-real-isa-integration.md) §11.1/§11.2.1，ADR-SOC-15 阶段 A） | 新 ISA 只需产出 `InstrDescriptor`；**依赖控制位随描述符走** |
| **`isa_type` 多前端开关**（`ptx` / `cdna3` / `rvv`） | 已设计 | 新 ISA 是**第三个前端**，不破坏 timing 宿主 |
| **OSF / MCOS 操作数供给层** | 设计目标（[`33-…`](./33-sm-operand-supply-design-target.md)） | **本文的核心资产**：带 tag 的操作数槽 ⇒ 硬件可校验"交付的是不是正确的值" |
| `W = 2`（读带宽供给） | 已裁决（33 号 §3.1） | 依赖层与带宽层**正交**：依赖层不改变读次数，只改变"何时可读" |

## 2. 设计空间：5 个候选

| # | 候选 | 机制 | 依赖面积 | 正确性保证者 | 编译器负担 | 关键优点 | 关键缺点 |
|---|------|------|---------|------------|-----------|---------|---------|
| **A** | **纯 NV 式** | Stall counter + 6×SB + DEPBAR + Yield | **0.09% RF** | **编译器** | 高（延迟表、槽分配、mask 编排） | 面积最小；并发依赖链最多（6） | **编译器提示错 = 结果错**；6 槽上限；WAR 需专用槽 |
| **B** | **纯 AMD 式** | TLB scoreboard（ALU 冒险）+ 类型化内存计数器 + `s_waitcnt` | 未公开量化（推测中） | **硬件** | 低（ALU 零负担；内存需显式 wait 指令） | ALU 依赖完全硬件保证 | 内存 wait 指令**占 issue 槽**；并发链仅 3–4；`s_waitcnt` 增加指令数 |
| **C** | **学术全 scoreboard** | 两块 per-register scoreboard（WAW/RAW + WAR） | **5.32% RF** | 硬件 | 零 | 最通用；无槽位上限 | 面积 59× 于 A；**实测更慢**（0.97×）；精度略差（14.87% vs 13.98%） |
| **D** | **NV + 早锁存不变式** | A + **新不变式 D-1** | **~0.09% RF** | 编译器（RAW/WAW） | 中 | **WAR 在 D-1 覆盖的类上消失**；面积同 A | 仍依赖编译器正确设置 stall count |
| **E** ⭐ | **D + 硬件 tag 兜底** | D + **操作数供给层 tag 校验架构化** | **≈0.15% RF** | **硬件（值身份）+ 编译器（时序）** | **低** | **复用/宽度提示 fail-safe**；WAR 消失；面积最小 | 依赖层不覆盖"纯时序"错误的编译器责任 |

> **A vs B 的本质分歧不是面积，是"谁对"**：A 把正确性押在编译器上（面积换人力），B 把正确性押在硬件上（面积换确定性）。**新 ISA 有第三条路（E）：把"值身份"的正确性交给硬件（tag 校验），只把"时序"留给编译器** —— 因为前者可以硬件兜底，后者不能。

## 3. 三家做法的机理剖析

### 3.1 NVIDIA：靠"编译期已知"取胜

| 机制 | 原文依据 | 隐含前提 |
|------|---------|---------|
| Stall counter（定长 RAW） | 「the compiler sets this counter with **the latency of the producing instruction minus the number of instructions between the producer and the first consumer**」 | **延迟是 ISA 常量**（I2） |
| 依赖计数器（可变延迟） | 「the producer increases a particular counter after issue, and **decreases it at write-back**」 | 变量延迟必须用计数器 |
| **WAR：读源时释放** | 「**the counter is decreased after the instruction reads its source operands**」 | **读者可能晚于写者取源** |
| 面积 | 41 bit/warp = **0.09% RF** | — |

> **NVIDIA 的核心手法**：**把"依赖"翻译成"等几个拍"**，从而让硬件只需要**几个计数器**而不是**每寄存器表项**。
> **代价**：编译期必须完全正确（论文实测：Stall counter 设错 ⇒「the result of the program is incorrect」）。

### 3.2 AMD：靠"硬件兜底 + 显式内存等待"取胜

| 机制 | 原文依据 | 隐含前提 |
|------|---------|---------|
| ALU 冒险由硬件处理 | 「**AMD does not need software or compiler intervention to avoid data hazards with ALU instructions**」 | 硬件有 TLB scoreboard |
| 内存依赖用 `waitcnt` | 「each wavefront has **three or four counters**, with each counter dedicated to specific instruction types」；「**AMD does not allow regular instructions to wait for a counter to reach zero using control bits**, requiring an explicit `waitcnt` instruction」 | 内存延迟不可预测 |
| RDNA 3/3.5 加 `DELAY_ALU` | 「introduced the DELAY_ALU instruction … to mitigate pipeline stalls caused by dependencies」 | 硬件 scoreboard 仍有停顿 |

> **AMD 的核心手法**：**ALU 依赖全部硬件化**（编译器零负担），**内存依赖用显式指令**（换取低解码开销）。
> **代价**：内存 wait 指令**占 issue 槽**、增加指令数；并发可变延迟依赖链仅 3–4 条。

### 3.3 学术方案：靠"通用"取胜

| 机制 | 依据 | 隐含前提 |
|------|------|---------|
| 两块 scoreboard（WAW/RAW + WAR） | arXiv:2503.20481 §2 / §7.5；GPGPU-Sim `checkCollision` | **无编译器负担** |
| 每 entry 63 个 consumer | 「Assuming support for up to **63 consumers per entry**, a single warp would require **2324 bits**」 | 假设"每 entry 需要数到 63 个消费者" |

> **学术方案的核心手法**：**用面积换通用性**。
> **代价（实测）**：5.32% RF 面积、**更慢**（0.97×）、精度略差。**且它的通用性在现代硬件上已被证明"过度"**——NVIDIA 实测用 0.09% 就够了。

### 3.4 可提炼的 4 条机制（应吸收）

| # | 机制 | 来源 | 吸收理由 |
|---|------|------|---------|
| **M-1** | **"等拍"化**：定长依赖翻译为 stall count | NVIDIA | 面积最小；延迟是 ISA 常量时可精确静态推理 |
| **M-2** | **"槽位化"**：可变延迟依赖用少量 per-warp 槽 | NVIDIA / AMD | 状态规模 ∝ 在飞生产者数，而非寄存器数 |
| **M-3** | **"早释放"**：依赖在**真正取走值**时解除，而非写回时 | NVIDIA（WAR） | 解除点越早，并发度越高（实测可提前数百拍） |
| **M-4** | **"显式内存等待"**：内存序用显式指令/计数器 | AMD（指令）/ NVIDIA（控制位） | 内存延迟不可静态推理；显式化让编译器可见 |

### 3.5 三条不可照搬的约束（必须回避）

| # | 约束 | 来自 | 新 ISA 的回避方式 |
|---|------|------|--------------|
| **X-1** | **"源读取可以晚于 issue"** ⇒ 产生 WAR 类依赖 | NVIDIA 的内存指令（`LDG.32` regular 的 WAR 释放点 = **+11 拍**，而 RAW/WAW = +32 拍） | **不变式 D-1**：所有指令类的源锁存窗口 ≤ 写可见延迟 ⇒ WAR 消失（§4.1） |
| **X-2** | **"每 entry 需要数到 63 个消费者"** ⇒ scoreboard 面积爆炸 | 学术方案的假设 | **不变式 D-2**：依赖状态规模 ∝ 在飞可变延迟生产者数（4–8），与寄存器数无关（§4.2） |
| **X-3** | **"复用提示是承重的"**（提示错 ⇒ 值错） | NVIDIA 的 `.reuse` 语义（read-once + re-arm，读到不匹配就 MISS，尚属安全，但"哪些值被缓存"完全由编译器控制） | **不变式 D-3**：复用/宽度提示**语义化**为「可被忽略的提示」，硬件按 tag 校验（§4.4） |

## 4. 推荐方案 E

### 4.1 不变式 D-1：源锁存窗口 ≤ 写可见延迟 ⇒ **WAR 收缩为 late-addr 一类**

#### 4.1.1 推导

记：`D_class` = 该指令类**全部源操作数被锁存的最晚时刻**（相对 issue）；`L_w` = **目的寄存器可见的最早时刻**（相对 issue，架构下界）。

```
同一 warp 内按序发射（R 读 R'，W 写 R'，R 在 W 之前）：
    R 发射于 t_r，源锁存最晚于 t_r + D
    W 发射于 t_w ≥ t_r + 1，R' 最早可见于 t_w + L_w ≥ t_r + 1 + L_w

⇒ 无 WAR 当且仅当   t_r + D  <  t_r + 1 + L_w   ⇔   D ≤ L_w
```

> **不变式 D-1**：**对每个指令类 `c`，要求 `D_c ≤ L_w_min`（全 ISA 统一的下界）。**
> 满足它 ⇒ **任何按序发射的"读者→写者"序列都不产生 WAR** ⇒ **对满足 D-1 的指令类，WAR 依赖不存在** ⇒ **不需要 WAR 计数器**（NVIDIA 需要），**不需要 WAR scoreboard**（学术方案需要）。
>
> ⚠ **范围限定（v1.3）**：这条只覆盖**满足 `D_c ≤ L_w,min` 的指令类**。**延迟地址访存类（§4.1.5）豁免 D-1**（`D_mem = 11 > 4`）⇒ 该类**仍会产生 WAR**，但其 WAR **不需要专用硬件状态**——由写者的 stall count 表达（§4.1.6，Q-11）。

#### 4.1.2 对照现有硬件

| 指令类 | `D`（源锁存最晚） | `L_w`（写可见最早） | 满足 D-1？ | 结果 |
|--------|------------------|--------------------|:---------:|------|
| NVIDIA ALU（定长） | 3（读窗） | 4（issue+3 进 FU，+4 出结果） | ✅ | 本就无 WAR |
| NVIDIA **访存**（`LDG.32` regular） | **11**（实测 WAR 释放点） | 4 | ❌ | **WAR 的唯一来源** |
| NVIDIA tensor / 其他可变延迟 | 更晚 | — | ❌ | 同上 |

> **NVIDIA 之所以需要 WAR 计数器，唯一原因是它的访存指令**（以及 tensor 类）**把源读取推迟到了 issue 之后很远**——因为它要等地址依赖与 cache 探测。这是**流水线效率的选择**，不是原理必需。**新 ISA 不必继承这个选择。**

#### 4.1.3 保留内存级并行度的折中

若把访存指令的源锁存严格压到 `issue` 拍，会损失"地址依赖未就绪时仍可先发射"的内存级并行度（MLP）。

> **允许有界推迟**：把 `D_mem` 设为一个**架构常量**（例如 `L_w_min = 4` ⇒ `D_mem ≤ 4`），即访存指令可在 issue 后**至多 4 拍**内锁存源操作数。
> **仍有 3–4 拍的 MLP 窗口**，但已远小于 NV 的 11 拍 ⇒ **WAR 不再出现**。
> **D-1 的检验方法**：这是**编译期可判定**的——只要 `D_c ≤ L_w_min` 对每个类成立，WAR 在架构上不可能发生。**建议新 ISA 把这组常量写进 ISA 规范并给出机械化检查。**

#### 4.1.4 参数落定（Q-4 / Q-6 已裁决）

| 参数 | 裁决值 | 含义 | 推论 |
|------|-------|------|------|
| `L_w,min` | **4** | 目的寄存器可见的最早时刻 = issue + 4 | 与 33 号 §4.4.1b 的 `d = 1`（FU 占用 1 拍）+ 读窗 3 拍**一致** |
| `D_ALU` | 3 | ALU 类源锁存在读窗内完成 | 3 ≤ 4 ✅ |
| **`D_mem`** | **≤ 4** | 访存类可在 issue 后**至多 4 拍**内锁存源 | 保留 **3–4 拍 MLP 窗口**；4 ≤ 4 ✅（**紧边界**） |

> ⚠ **`D_mem = L_w = 4` 是紧的边界**（`D ≤ L_w` 取等）。若未来把 `L_w` 降到 3，`D_mem` **必须同步降到 3**。
> ⇒ **ISA 规范应写不变式 `D_c ≤ L_w,min`（而非硬编码 4）**，并给出**机械化检查**：逐指令类核对 `D_c` 与 `L_w` 常量表（即 E-14 的查询表）。

#### 4.1.5 「延迟地址访存」类与 WAR 的收缩（**v1.2 新增，Q-9 分析结论**）

> **问题**：不变式 D-1 消灭 WAR 的前提是"**所有访存指令的地址源都能在 `D_mem = 4` 内就绪**"。对**地址链**（pointer-chasing、长依赖链）不成立 ⇒ 该类访存若强制 4 拍内锁存源，就**必须等到地址依赖就绪才能发射**。

**代价的准确定性（重要）**：

| 现象 | 是否真损失 | 说明 |
|------|:---------:|------|
| "访存请求发出更晚" | ❌ **不是** | NVIDIA 的访存同样要等地址就绪才发请求（实测 WAR 释放点 = **+11 拍**，即源在 11 拍后才读）⇒ **地址链上的访存在两边都是串行的** |
| "地址链的 MLP 下降" | ❌ **不是** | 同上，两边都串行 |
| **"等地址"的等待位置** | ✅ **是** | NVIDIA：等待发生在**访存单元内部**（指令已发射，占 LSU 队列槽，**不占 issue 槽**）⇒ 调度器可继续发别的 warp<br>新 ISA：等待发生在 **issue 端**（指令**未发射**）⇒ 该 warp 的发射资格被占住 |
| **WAR 窗口** | ✅ **是（净收益）** | 11 拍 → 4 拍 ⇒ **写者被阻塞时间减少 7 拍** ⇒ 对**所有** kernel 都是净收益 |

> ⇒ **净效果**：D-1 用"所有 kernel 少 7 拍写者阻塞"，换"pointer-chasing 类 kernel 的 issue 端等待"。**这是可接受的取舍，但必须可测**（Q-9）。

**方案（建议）**：**引入一类豁免指令**，而不是一刀切。

| 项 | 内容 |
|---|---|
| **类名** | **延迟地址访存（late-addr load/store）** |
| **触发** | **编译器显式标注**（指令编码 1 bit）——仅在地址依赖确实无法早满足时使用 |
| **`D_mem`** | **11**（豁免 D-1），即恢复 NVIDIA 口径的源读取时机 |
| **代价** | **仅编译期责任**：写该指令源寄存器的指令必须自带 `stall`（§4.1.6，Q-11）⇒ **WAR 收缩到这一类，且不需要任何专用硬件状态** |
| **收益** | pointer-chasing 类 kernel 不损失 issue 端吞吐 |
| **判据** | 编译器判定规则：地址源能否在 4 拍内就绪？不能 ⇒ 标 `late-addr` |

> ⚠ **v1.3 更正**：v1.2 曾写"Q-1 的 WAR 槽从保守变为必需"。**该结论错误** —— 见 §4.1.6：late-addr 类的 WAR 用**写者已有的 4-bit stall** 就能精确表达，不需要独立的 WAR 计数器，也不需要任何新编码位。**Q-1 因此被 Q-11 取代**（WAR 槽取消）。

### 4.1.6 WAR 的精确机制：用写者的 stall count 表达（**Q-11，v1.3**）

> **要解决的现象**：late-addr 读者 `R` 在 `i_r + D_mem`（`D_mem = 11`）才锁存源；若写者 `W` 的写可见时刻早于该时刻，`R` 读到被覆盖的新值 ⇒ **WAR 事故**。

**推导**（全部量都是编译期已知的静态量）：

```
R 的源锁存时刻      = i_r + D_mem
W 的写可见时刻      = i_w + L_w          （L_w = L_w,min = 4，Q-6）
要求               i_w + L_w  >  i_r + D_mem
⇔  发射距离 d = i_w − i_r  >  D_mem − L_w,min
⇔  d ≥ D_mem − L_w,min + 1 = 8           （D_mem = 11, L_w = 4）
```

| 情形 | 编译器动作 |
|------|-----------|
| `d ≥ 8` | **无需动作**（发射距离天然满足） |
| `d < 8` | 在 `W` 上置 `stall = 8 − d`（**最坏 `d = 1` ⇒ `stall = 7`**） |

> **⇒ 需要表达的最大 stall = `D_mem − L_w,min` = 7，而 4-bit stall 上界为 15** ⇒ **恒可表达**。

**由此得到一条可机械检查的替代不变式**（取代"用 WAR 槽兜底"）：

> **不变式 D-1'（WAR 可表达性）**：**对任何豁免 D-1 的指令类 `c`，必须满足 `D_c − L_w,min ≤ 15`。**
> 满足它 ⇒ **该类产生的全部 WAR 都可用现有 `stall` 字段表达** ⇒ **ISA 不需要 WAR 计数器、WAR scoreboard 或 WAR 槽位**。
> 检查方式：与 E-14 的 `{D_c, L_w,c}` 表一并机械核对（`11 − 4 = 7 ≤ 15` ✅）。

**为什么这条在"warp 被换出"时仍然安全**（这是唯一需要论证的漏洞）：

> `stall` 以**本 warp 的发射机会**计数。warp 被换出时，`R` 的流水线继续推进的 wall-clock 时间**只增不减** ⇒ 实际经过时间 ≥ 发射槽间隔 ⇒ `R` 的源锁存**只会更早**完成 ⇒ **保守安全**。
> 反向（把 `stall` 误解为 wall-clock 周期）也不破坏正确性：wall-clock 计数只会让 `W` 更晚发射。

> **一句话**：`stall` 字段本来就是"等几拍"，而 WAR 需要的正是"等几拍"——**不需要第二种机制**。
> **对照 NVIDIA 为何用 WAR 计数器**：它的 WAR 释放点（+11/+14 拍）是**硬件内部行为**、且其调度器允许更激进的乱序；本 ISA 的 `D_mem` 是**架构常量**且发射严格按序 ⇒ 静态可算 ⇒ 计数器是多余的。

### 4.2 不变式 D-2：依赖状态规模 ∝ 在飞可变延迟生产者数

#### 4.2.1 推导

| 依赖类型 | 需要的硬件状态 | 规模取决于 |
|---------|------------|-----------|
| RAW / WAW（**定长**） | **无**（编译器 stall count） | — |
| RAW / WAW（**可变延迟**） | per-warp 槽（槽 id + 计数） | **在飞可变延迟生产者数** |
| WAR | **无专用状态**（D-1 覆盖的类不存在；late-addr 类用写者 `stall`，Q-11） | — |
| 内存依赖 | per-warp 类型化计数器 | 在飞访存数 |

> **在飞访存数有硬件上界**：Ampere 实测「each sub-core can buffer up to **five** consecutive instructions」（第 6 条起停顿），论文估计队列深度为 **4**。
> ⇒ **一个 warp 最多同时有 4–8 个可变延迟生产者** ⇒ **per-warp 依赖槽只需 4–8 个**，而不是"每寄存器一项"。

#### 4.2.2 面积对比

| 方案 | 依赖状态面积 | 备注 |
|------|------------|------|
| 学术全 scoreboard | **5.32% RF** | 332 entries/warp × 63 consumers |
| NVIDIA 式（6 SB + stall + WAR 槽） | **0.09% RF**（41 bit/warp） | 6 槽已含 WAR |
| **新 ISA（D-1 + D-2，Q-2/Q-11 裁决后）** | **≈0.121% RF** | **53 bit/warp**：`SB[8]×6 + stall 4 + yield 1`（**v1.3：Q-11 取消 `WAR[2]×6`**）；**48 warp/SM** 基数 |

> **量级对比（48 warp/SM 基数，RF = 2,097,152 bit）**：新 ISA **0.121%** = 学术方案的 **1/44**、NVIDIA 现状的 **1.3×**。
> **校正链**：v1.0 写"≈0.02–0.04%"**有误**（漏算槽位增量）；v1.1 按 Q-1（独立 WAR 槽）+ Q-2（固定 8 槽）得 65 bit ⇒ 0.149%；**v1.3 按 Q-11 取消 WAR 槽得 53 bit ⇒ 0.121%**（`8×6 + 4 + 1 = 53`）。
> ⚠ **诚实结论**：新 ISA 的依赖层**比 NVIDIA 现状（41 bit）贵 1.3×**——差价来自**8 槽（NVIDIA 6 槽）+ 逐指令 8-bit mask**，即"更多在飞可变延迟生产者"，**不是**为 WAR 付钱（Q-11 已把它变成零成本）。
> ⚠ **诚实标注**：面积估算**未经综合验证**，且**"槽按在飞生产者数而非 6 固定"要求编译器做槽分配**（回到 NV 的负担）——**这是一个 trade-off，不是免费午餐**（§7 D-2）。

### 4.3 不变式 D-3：复用/宽度提示**语义化**（fail-safe）

#### 4.3.1 现状对比

| | NVIDIA `.reuse` | 新 ISA（推荐） |
|---|----------------|--------------|
| 语义 | 编译器指示"缓存此操作数"；**读一次即失效**；消费者需自置 `.reuse` 才能续链 | 编译器指示"**此操作数可被复用**"——**纯提示** |
| 提示错误的后果 | 可能**多命中/少命中**（性能）；语义复杂（read-once + re-arm） | **仅性能**；语义简单 |
| 硬件校验 | tag 匹配（同 warp + reg + op_pos） | **同，且被提升为架构保证** |

#### 4.3.2 架构保证（建议写进 ISA 规范）

> **架构保证 A-1（值身份）**：**经操作数槽交付给消费者的值，与其被读取时寄存器堆中对应 `(warp, reg)` 的值逐位相同。**
> **架构保证 A-2（槽生命周期）**：**槽中值在寄存器被改写时立即失效**（write-invalidate）；**失效不改变任何指令的可观察语义**。
>
> ⇒ **推论**：编译器对**复用提示 / 宽度提示**的任何错误，**只影响性能（命中/未命中、读位宽），绝不产生错误值**。

> **这是新 ISA 相对 NV / AMD 的核心增量**：
> - NV 的正确性责任**全部**在编译器（Stall counter + `.reuse` + 槽分配）。
> - 新 ISA 把**值身份**的正确性收归硬件（A-1/A-2 + tag 校验），只保留**时序**正确性在编译器。

#### 4.3.3 与 33 号文档的一致性

33 号文档 §4.1.2 的证明（第 1–8 条）已经给出"**槽值恒等于 RF 当前值**"的可证论证 ⇒ **A-1/A-2 不是新命题，而是把既有设计目标的正确性论证提升为架构保证**。33 号文档 §7.2（fail-safe 表）已逐条核对。

### 4.4 ISA 可见元素清单（新 ISA 需定义什么）

| # | 类别 | 元素 | 说明 |
|---|------|------|------|
| **E-1** | 编码 | **stall count（4 bit）** | 定长 RAW/WAW 的"等拍"（M-1） |
| **E-2** | 编码 | **dep slot id（3 bit）+ wait mask（8 bit）** | 可变延迟 RAW/WAW；**固定 8 槽（Q-2）⇒ id 3 bit、mask 8 bit**。**`wait_mask` 只覆盖 SB[8]**：WAR 不占任何 mask 位（Q-11） |
| **E-3** | 编码 | **reuse flags（3 bit，每 op_pos 1 bit）+ budget hint（2 bit）**（**v1.3 修正**：v1.2 误写为 "reuse 2 + width 2"，漏 `budget_hint`） | **纯提示**，语义由 A-1/A-2 兜底。**`width hint` 不进控制块**——由 opcode 变体承载（Q-10）；**仅向量域**（MCOS 槽键为 `(bank, op_pos)`） |
| **E-4** | 编码 | **yield（1 bit）** | 跨 warp 切换（+1 cycle） |
| **E-5** | 编码 | ~~operand source（每源 2 bit）~~ | **Q-5 裁决"先隐式" ⇒ 不需要该字段**：硬件对**每个**源操作数都做槽 tag 匹配（NVIDIA RFC 同构），编译器无需告知"哪个操作数走槽" |
| **E-6** | **不变式** | **D-1：`D_c ≤ L_w_min`（逐指令类）/ D-1′：豁免类的 `D_c − L_w,min ≤ 15`** | WAR 收缩/可表达的根据；**两条都须可机械检查**（§4.1.6，Q-11） |
| **E-7a** | **不变式/架构契约** | **每 warp 可区分的在飞可变延迟生产者 ≤ 8（固定槽数）** | 状态规模的根据。**这是架构契约**：冻结后**不得靠加深硬件队列来突破**（否则编译器可能产生 > 8 个在飞生产者而无法表达） |
| **E-7b** | **规范·槽耗尽规则** | **编译器在超过 8 个在飞可变延迟生产者时必须二选一：① 合并到同一槽（`wait_mask` 同位置位 ⇒ 并集等待）；② 插 `dep.wait` 排空** | **v1.3 补全**（v1.2 缺失 ⇒ 槽耗尽无定义）。**死锁自由性**：生产者必然完成 ⇒ 计数必然归零 ⇒ 两种退路都不会永久阻塞 |

| **E-11** | 指令 | **`mem.fence` / `mem.wait`** | 内存序；可与 `dep.wait` 合并为一个带类型的指令 |

### 4.5 编码宽度裁决（**Q-2 / Q-3 / Q-5 / Q-10 / Q-11 落定，v1.3 重算**）

> ⚠ **v1.3 重算说明**：v1.2 的表用 **4-bit opcode + 6-bit 寄存器索引**推出"典型 3 源 ALU 恰好 48 bit"。但 38 号已定 **128 SGPR（7 bit）/ 256 VGPR（8 bit）** ⇒ **该推演的字段宽度是错的，结论也不能沿用**。下表按真实字段重算（opcode 统一 **11 bit = fmt 3 + op 8**）。

#### 4.5.1 控制块按域裁剪（**Q-10**）

```
向量域控制块（21 bit）                标量域控制块（16 bit）
    stall count      4                    stall count      4
    dep slot id      3                    dep slot id      3
    wait mask        8                    wait mask        8
    reuse flags      3                    yield            1
    budget hint      2                  ────────────────────────
    yield            1                    合计            16
  ────────────────────────
    合计            21
```

**三条裁剪依据（逐条可验）**：

| # | 依据 | 省下 |
|---|------|------|
| 1 | `reuse_flags` / `budget_hint` **只作用于 VGPR**（MCOS 槽键 = `(bank, op_pos)`，33 号）⇒ 标量域无此语义 | 5 bit（标量域） |
| 2 | `width_hint` 由 **opcode 变体**承载（窄值算术是独立 opcode），不占控制位 | 2 bit（两域） |
| 3 | **WAR 不需要任何字段** —— Q-11 用写者 `stall` 表达（§4.1.6） | 3 bit（两域） |

> **⇒ 原 26 bit 的两域统一口径作废**；向量 21 bit、标量 16 bit 是**唯一口径**（39 号 §6、40 号 §3 同步）。

#### 4.5.2 编码表（真实字段宽度）

| 形态 | 域 | opcode | 寄存器/立即数字段 | 控制块 | 合计 | 长度 |
|------|:--:|:------:|-----------------|:------:|:----:|:----:|
| SOP1（1 源 + dst） | 标量 | 11 | 2×7 = 14 | 16 | 41 | 48 |
| **SOP2（2 源 + dst）** | 标量 | 11 | 3×7 = 21 | 16 | **48** | **48 精准** |
| SOPC（2 源 → SCC） | 标量 | 11 | 2×7 = 14 | 16 | 41 | 48 |
| SOPP（控制流 / 16-bit 立即数） | 标量 | 11 | imm16 = 16 | 16 | 43 | 48 |
| SOPK（1 源 + imm16） | 标量 | 11 | 7 + 16 = 23 | 16 | 50 | 64 |
| **VOP1（1 源 + dst）** | 向量 | 11 | 2×8 = 16 | 21 | **48** | **48 精准** |
| VOP2 / LSU（2 源 + dst） | 向量 | 11 | 3×8 = 24 | 21 | 56 | 64（8 bit 留作 imm8 / cache 策略） |
| **VOP3（3 源 + dst）** | 向量 | 11 | 4×8 = 32 | 21 | **64** | **64 精准** |

> **⇒ 结论（v1.3 修正版）**：
> - **48-bit 形态 = 全部标量算术形态（SOP1/SOP2/SOPC/SOPP）+ 向量 1 源（VOP1）**；**标量域只有 SOPK（带 16-bit 立即数）升到 64-bit**。
> - **向量域的 2 源 / 3 源主力形态一律 64-bit** —— 48-bit **不**承载向量 2/3 源（v1.2 的"48 bit 刚好装下典型 3 源 ALU"在真实字段下**不成立**）。
> - 仍采用 **48/64 双长度、16-bit 粒度**（Q-3 结论不变，论证已换）。
> **对照**：CDNA 32-bit 定长 ⇒ **装不下**（控制块 16/21 bit 已占去一半）；NVIDIA SASS 128 bit ⇒ 富余。
> ⚠ **"标量域多数 48-bit" 是待测假设，不是结论**：标量代码立即数密集（地址、循环界、常量），SOPK 占比若达 30–50%，则标量流的平均长度接近 56 bit。**该比例只能在 B-2 汇编器可用后对代表性 kernel 统计**，在此之前不得把它写成取指带宽收益。

#### 4.5.3 取指与长度判定（**B-0 必须冻结的四条**）

| 项 | 规定 |
|---|---|
| **长度判定** | 由 **`fmt`（指令首 3 bit）** 唯一决定：`fmt ∈ {SOP1,SOP2,SOPC,SOPP,VOP1}` ⇒ 48 bit；`fmt ∈ {SOPK,VOP2,VOP3}` ⇒ 64 bit ⇒ **解码只需 2 字节前瞻**（`fmt` 位于指令首音节最低 3 bit） |
| **对齐** | 指令起点 **2 字节对齐**（48 = 3 音节、64 = 4 音节 ⇒ 不变量成立）；无更强对齐要求 |
| **跨取指窗** | 取指窗 **16 字节**；指令**允许跨界**，解码器持 1 条 carry-over 缓冲，跨界时多用一次下一窗取指 |
| **分支目标粒度** | **2 字节**（与对齐单位一致）；`SOPP` 的分支偏移以 2 字节为单位编码 |

> ⚠ **CppTLM 侧不受此约束**：`InstrDescriptor` 是 128 字节的结构化描述符（非编码），依赖控制块（向量 21 bit）放其中。

## 7. 设计参数裁决记录（Q-1..Q-6）

> **命名更正（v1.1）**：本文 v1.0 把"设计参数"编号为 `D-1..D-6`，与 §4 的三条**不变式 D-1/D-2/D-3** 撞名。v1.1 起：**不变式保留 `D-1/D-2/D-3`，设计参数改称 `Q-1..Q-6`**。

| # | 问题 | **裁决** | 后果与实现约束 |
|---|------|---------|--------------|
| **Q-1** | WAR 槽与 SB 槽是否物理合并？ | ~~✅ **分开**~~ ⇒ **v1.3 被 Q-11 取代（WAR 槽取消）** | `WAR[2] × 6 bit = 12 bit/warp` **独立占用**。理由：**两者释放事件不同**（WAR 在"读完源"，RAW/WAW 在"写回"）⇒ 合并会让一个槽承载两种释放时刻，编译器须保证两类依赖不交错 ⇒ 不合理的负担 + 假阻塞。代价 +12 bit/warp（v1.2 时计入 65 bit/warp）。**v1.3：本条已被 Q-11 取代 —— WAR 不需要任何专用状态，12 bit/warp 的代价归零** |
| **Q-2** | 依赖槽数按在飞数（4–8）动态取，还是固定？ | ✅ **固定 8** | `SB[8]`、slot id **3 bit**、wait mask **8 bit**（不是 6）。面积 `8×6 = 48 bit/warp`。**编译器负担不增加**（槽数静态可知，可做静态分配）；覆盖最坏在飞可变延迟生产者数（实测上界 4–5） |
| **Q-3** | 新 ISA 编码宽度 | ✅ **≥48 bit 变长** | **v1.3 重算**（§4.5.2，按 11-bit opcode + 7/8-bit 寄存器字段）：**48-bit = 全部标量算术形态（SOP1/2/C/P）+ VOP1**；**64-bit = SOPK / VOP2 / VOP3**（向量 2/3 源主力全在 64-bit）。⇒ 采用 **48/64 bit 双长度、16-bit 粒度**。**不可采用 32 bit 定长（CDNA 风格）** —— 控制块 16/21 bit 已占去一半 |
| **Q-4** | `D_mem`（访存源锁存窗口上限） | ✅ **= `L_w,min`（≈4）** | 保留 **3–4 拍 MLP 窗口**；`D_mem = 4 ≤ L_w = 4`（**紧边界**，见 §4.1.4）。**ISA 规范须写不变式 `D_c ≤ L_w,min` 而非硬编码 4** |
| **Q-5** | 操作数供给：显式 ISA 资源还是隐式提示？ | ✅ **先隐式**（E-3 复用/宽度提示） | **删除 E-5（operand source 字段）**，省 6 bit；硬件对**每个**源操作数都做槽 tag 匹配（NVIDIA RFC 同构）。显式 `reuse.publish`（E-13）**留作扩展**——变长编码使其可在后期以新指令形态加入，无需改既有编码 |
| **Q-6** | `L_w` 架构下界 | ✅ **= 4** | 与 33 号 §4.4.1b 的 `d = 1` + 读窗 3 拍**一致**（`issue+3` 进 FU、`issue+4` 结果可见）。**与 Q-4 联动**：`D_mem ≤ 4` |

| **Q-7** | 计数器位宽：6 bit（63）vs 4/5 bit + "槽满即停发"语义 | ✅ **裁决：6 bit** | 沿用 NVIDIA 的已验证宽度（63 上限），**不引入"槽满即停发"的新语义**（少一处实现复杂度）。面积锁定 **0.121% RF**（v1.3：Q-11 取消 WAR 槽后重算；v1.2 的 0.149% 作废）；4 bit 的 ~0.091% 留作后续实测驱动的优化项 |
| **Q-8** | 新 ISA 与既有 ISA（PTX / CDNA3 / SASS）的关系 | ✅ **裁决：取代关系** —— **新 ISA 是本仓 GPGPU 的唯一 ISA**；其余 ISA **降级为调研与参考**（行为基线 / 延迟分档 / 先例），**不再是实现目标** | 详见 [`37-new-isa-design-charter.md`](./37-new-isa-design-charter.md)（ISA 设计总纲）。**连锁影响**：ADR-SOC-15 Phase C（CDNA 引擎接入）被取代（需 superseding ADR）；13 号 CDNA-EMU 选型**作废**；11 号双轨前端**范式保留、收敛为单一前端**；12 号校准基线的**方法论保留、对标对象改为 NVIDIA/AMD 实测延迟表** |

| **Q-10** | **控制块位宽**：两域统一 26 bit，还是按域裁剪？ | ✅ **裁决：按域裁剪 —— 向量 21 bit / 标量 16 bit** | 三条裁剪依据见 §4.5.1（`reuse/budget` 仅向量域；`width_hint` 转 opcode 变体；Q-11 取消 WAR 字段）。**连锁**：39 号 §6 元数据表、40 号 §3 编码章同步；**向量 3 源 64-bit 形态在 21 bit 下恰好装满**（11+32+21=64） |
| **Q-11** | **late-addr 类的 WAR 如何表达**：专用 WAR 槽 / 硬件 scoreboard / 写者 stall？ | ✅ **裁决：写者 `stall`（零硬件状态、零编码位）** | 推导见 §4.1.6：`d ≥ D_mem − L_w,min + 1 = 8`，最坏需 `stall = 7 ≤ 15` ✅ ⇒ 不变式 **D-1′：`D_c − L_w,min ≤ 15`**。**取消了 Q-1 的 `WAR[2]×6`**，面积 0.149% → **0.121%**；`wait_mask` 只覆盖 SB[8] |

| 检查项 | 结果 |
