## 0. TL;DR

> **一句话**：**连续 3 源指令序列与连续 2 源指令序列的 IPC 差距，不来自"2 源序列浪费了读带宽"，而来自"3 源序列每条指令多花 1.5× 的读带宽"**；因此**一切"减少读"的机制（MCOS）只在 3 源密集负载上有 IPC 收益**，而在 2 源密集负载上收益为 **0**。

| # | 结论 | 章节 |
|---|------|------|
| **①** | **连续 3 源序列（FFMA）IPC = 0.667；连续 2 源序列（FADD/FMUL）IPC = 1.000** —— 相差 **1.50×**（per sub-core，warp-inst/cycle，`W=2`） | §3 |
| **②** | **两条序列的读端口利用率都是 100%**。"2 源序列浪费 33% 读带宽"**不成立** → ERW 在稳态下**没有带宽余量可回收**，其 IPC 收益为 **0** | §3.3 / §3.5 |
| **③** | **MCOS 的 IPC 收益只存在于 3 源序列**：3 源 → 2 读时 IPC 触顶 1.000（**+50%**），再降到 1 读不再涨（被发射宽度卡住）。**2 源序列 MCOS 收益 = 0%** | §3.4 |
| **④** | **全部结论对读带宽供给 `W` 敏感**：`W=2` → 3 源流 0.667、MCOS +50%；`W=3` → 3 源流 1.000、**MCOS 的 IPC 收益归零**。✅ **v1.1 已裁决 `W = 2`**（33 号文档 §3.1.1）——**但「3 源流达到 1 warp-FFMA/cycle 峰值」的前提是「每条指令 ≥1 个操作数由 MCOS 供给」**（§4.1.4） | §4.1 |
| **⑤** | **上游实测弹性 ≈ 0.4**（CORF：读 −10% → IPC +4%；CORF++：读 −23% → IPC +9%），远低于模型的 1.0 → **IPC 目标不应按线性外推承诺** | §4.2 |

**时序结论**：读源窗口 `L=3`、ALU 深度 `d=1` ⇒ `Execute = issue+3`、结果可用 `= issue+4`、写回/FILL `= issue+4`、**依赖链率 = 4 cycle/条**（与 P1 实测一致）——见 §5。

## 1. 分析对象与边界

### 1.1 分析单元

本文**以 1 个 sub-core 为分析单元**（不是整个 SM），理由：

| 事实 | 证据 |
|------|------|
| 每 SM **4 个 warp scheduler** | [`05-sm-compute-unit.md`](./05-sm-compute-unit.md):255 |
| 每 scheduler **每 cycle 发 1 条** warp 指令 | 同上:256 |
| scheduler 与 sub-core **静态绑定**（`warp_id % 4`） | [`15-sm-microarchitecture-design.md`](./15-sm-microarchitecture-design.md):149 |

⇒ **1 scheduler = 1 sub-core = 2 个 RF bank**，故"发射宽度"与"读带宽供给"都按 sub-core 计。

## 2. 模型

### 2.1 参数

| 参数 | 含义 | 取值 | 来源 |
|------|------|------|------|
| `I_issue` | 每周期发射条数 | **1** | 05-sm-compute-unit.md:256 |
| `W` | 每周期可供给的 **warp 寄存器读数** = bank 数 × 每 bank 读口数 | **2**（文档口径）/ **3**（峰值口径）/ **1**（v0.3 ERW 图口径，**已废弃**） | 33 号文档 §3.1 |
| `k` | 指令的源操作数个数 | 3（FFMA）/ 2（FADD、FMUL） | — |
| `r` | 每条指令实际需要的 RF 读数 = `k` − 被 MCOS 命中的数 | 视场景 | — |
| `b₀, b₁` | 该指令落在 bank0 / bank1 的源个数 | `max_b = max(b₀,b₁)` | — |
| `max_b_avg` | **跨指令平均后**单 bank 的最大槽位负载 | 视场景 | — |

> **1 次读 = 1 个 warp 寄存器**（32 线程 × 32 bit = 1024 bit）。**窄读（WABR）只减位宽、不减读次数**，故不进入 `W`。

### 2.2 稳态吞吐上界

```
IPC_max = min( I_issue , W/r , 1/max_b_avg )
           发射宽度    读带宽总量   单 bank 槽位占用
```

**推导**：稳态下第 `i` 条指令占用 `r` 个读槽；按 bank 摊开后，bank `b` 的平均负载为 `n·avg(b₀,b₁)` 槽/拍，不得超过 1 槽/拍 → `n ≤ 1/max_b_avg`。同时总需求 `n·r ≤ W`。加上发射宽度上限，三者取最小。

## 3. IPC 分析

### 3.1 模型自洽性验证（**先证明模型对，再用它下结论**）

用上游**实测气泡数据**反查模型：

| 实测项（arXiv:2503.20481 §5.3 原文） | `max_b` | 模型预测气泡 `max_b − 1` | 实测气泡 | 模型稳态 IPC `1/max_b` | 吻合 |
|---|---|---|---|---|---|
| FMUL 两源**跨** bank → 无气泡 | 1 | 0 | **0** | 1.000 | ✅ |
| FMUL 两源**同** bank → 1 拍气泡 | 2 | 1 | **1** | 0.500 | ✅ |
| FFMA 三源**全同** bank → 2 拍气泡 | 3 | 2 | **2** | 0.333 | ✅ |
| FFMA 三源 2+1 分布（推得） | 2 | 1 | — | 0.500 | ✅（推得） |

**四个数据点全部吻合** ⇒ 模型可用。

> **副产品结论（关键）**：气泡 = `max_b − 1` 这一关系**只有在"端口跨指令预约共享"模型下成立**。若端口是"每指令独占"，FMUL 同 bank（只需 2 拍）本可塞进 3 拍窗口 → 应为 **0 气泡**，与实测矛盾。
> ⇒ **33 号文档 v0.3 的"窗口独占"前提被证伪**，ERW 的收益量化据此重写（v0.4 §4.2）。

### 3.2 表 1 — 连续 **3 源**序列（FFMA），`W = 2`

| 源分布 | `r` | `max_b_avg` | **IPC** | **IPC/SM**（4 子核） | 气泡/指令 | 瓶颈 |
|-------|-----|------------|-------|------------------|---------|------|
| 编译器均衡（跨指令交替 2+0 / 0+2） | 3 | 1.0 | **0.667** | 2.67 | 1 | 读带宽总量 |
| 固定 2+0（不交替） | 3 | 2.0 | **0.500** | 2.00 | 1 | 单 bank 槽位 |
| 三源全同 bank（最坏） | 3 | 3.0 | **0.333** | 1.33 | 2 | 单 bank 槽位 |
| **MCOS：1 个操作数被复用** | **2** | 1.0 | **1.000** | 4.00 | 0 | 发射宽度 |
| MCOS：2 个操作数被复用 | 1 | 0.5 | **1.000**（触顶） | 4.00 | 0 | 发射宽度 |

### 3.3 表 2 — 连续 **2 源**序列（FADD / FMUL），`W = 2`

| 源分布 | `r` | `max_b_avg` | **IPC** | **IPC/SM** | 气泡/指令 | 瓶颈 |
|-------|-----|------------|-------|---------|---------|------|
| 两源跨 bank（编译器可达） | 2 | 1.0 | **1.000** | 4.00 | 0 | 发射宽度 |

| **MCOS：1 个操作数被复用** | 1 | 0.5 | **1.000**（**+0%**） | 4.00 | 0 | 发射宽度 |

### 3.4 读端口槽位占用图（**IPC 差距的物理来源**）

```
连续 3 源（FFMA，IPC = 0.667）            连续 2 源（FADD，IPC = 1.000）
cycle  0    1    2    3    4    5         cycle  0    1    2    3    4    5
b0     I0   I0   I1   I2   I2   I3       b0     J0   J1   J2   J3   J4   J5
b1     I0   I1   I1   I2   I3   I3       b1     J0   J1   J2   J3   J4   J5
发射   I0   I1    —   I2   I3    —        发射   J0   J1   J2   J3   J4   J5
       └ 4 条 / 6 拍 = 0.667               └ 6 条 / 6 拍 = 1.000
读端口利用率 100%（2/2 槽全用）             读端口利用率 100%（2/2 槽全用）
```

> **这张图是全文最重要的一张**：两条序列的**读端口利用率完全相同（都是 100%）**。
> ⇒ **差距不是"2 源序列浪费了带宽"，而是"3 源序列每条指令多消耗 1.5× 的带宽"**。
> ⇒ **ERW 无法在 2 源序列上回收任何带宽**（已经 100%）。

**连续 3 源 + MCOS（1 个操作数被复用，`r`=2，IPC = 1.000）**：

```
cycle  0    1    2    3    4    5
b0     I0   I1   I2   I3   I4   I5      ← 每条指令只占 2 个槽（1 个来自 MCOS）
b1     I0   I1   I2   I3   I4   I5
发射   I0   I1   I2   I3   I4   I5      ← 读端口仍 100%，但发射率翻到 1.0
```

### 3.5 三条结论

1. **收益拐点在 `r = W = 2`**：3 源 → 2 读时 IPC 触顶 1.000（被发射宽度卡住），再降到 1 读**不再涨**，只余能耗与冲突收益。
2. **MCOS 的 IPC 收益只存在于 3 源密集负载**。2 源密集负载已同时打满发射宽度与读端口 → **MCOS / ERW / WABR 在 IPC 维度全部为 0 收益**（只余能耗与冲突收益）。**这是 OSF 的适用边界**（33 号文档 §4.1.4b 结论 2 / §6.1）。
3. **WABR 不改变 IPC**：它减的是**位宽**不是**读次数**，槽位占用不变 → 冲突频率不变 → IPC 不变（与 33 号文档 §4.3.2 的"冲突频率不因此下降"一致）。

## 4. 敏感性与边界

### 4.1 表 3 — `W` 敏感性（**全部结论的枢轴**）

| `W` | 3 源序列基线 IPC | 3 源序列 MCOS 后 IPC | **MCOS 的 IPC 收益** | 2 源序列 IPC | 3 源/2 源差距 | 状态 |
|-----|--------------|------------------|------------------|------------|------------|------|
| **1**（v0.3 ERW 图口径） | 0.333 | 0.500 | +50% | 0.500 | 0.67× | ❌ **已废弃**（与同文档硬件口径自相矛盾） |
| **2**（33 号文档 §3 硬件口径） | **0.667** | **1.000** | **+50%** | **1.000** | **0.67×** | ✅ **v1.1 裁决采纳** |
| **3** | **1.000** | 1.000 | **0%** | 1.000 | **1.00×** | ❌ 不采纳（需第 3 组 1024-bit 读写口） |

**三个口径的来源与冲突**：

| 口径 | 来源 | 与硬件峰值是否自洽 |
|------|------|------------------|
| `W = 1` | 33 号文档 v0.3 §4.2.2 的 ERW 图（单条 3 级流水，1 source/cycle） | ❌ 且与同文档 §3 的 2 bank 口径**自相矛盾**；**v0.4 已删除该图** |
| `W = 2` | 33 号文档 §3 表 + §8.3 config（`bank_count: 2` × `read_ports_per_bank: 1`） | ⚠ **不自洽**：Ampere 128 FP32/cycle/SM = 4 sub-core × 1 warp-FFMA/cycle ⇒ 每 sub-core 需 **3** 读/cycle，而 `W=2` 只供 2 |
| `W = 3` | 由硬件峰值反推 | ✔ 自洽，但**上游文献未直接给出**该数字 |

> **结论**：`W` 是**建模口径参数**与**硬件断言**的混合体，必须显式裁决（33 号文档开放项 **O-1** / backlog **V9**）。
> **本仓建议**：把 `W` 作为 TLM 的**显式可配参数**（`read_ports_per_bank` 可配到 2），使敏感性对照可复现，而不是先赌一个口径。

### 4.1.1 峰值可达性分析（**v1.1 新增：`W = 2` 与硬件峰值并非"不自洽"**）

> **v1.0 的表述有误**："`W = 2` 与 128 FP32/SM/cycle 峰值不自洽"。正确的关系是：

```
1 warp-FFMA/cycle/sub-core  ⇒  每拍需 3 次源读
W = 2                       ⇒  每拍只供 2 次读   ⇒  缺口 1 次读/指令

⇒ 峰值可达  ⟺  每条 3 源指令至少有 1 个操作数【不占 bank 读槽】
                 （由 RFC / MCOS 供给，或由编译器复用消除）
```

⇒ **`W = 2` 与峰值是自洽的，条件是"存在操作数复用"**——而这正是 RFC 存在的理由，也正是 **MCOS 的存在理由**。

**RFC 存在性 = `W = 2` 的最强证据**（v1.1 补）：

| 实测 | 含义 |
|------|------|
| CUTLASS sgemm **关掉 RFC → 0.79×** | RFC 是"够用与不够用"的分界线 |
| **35.9% 的静态指令**至少 1 个操作数走 RFC | 复用是常态而非特例 |
| Ampere §7.4：1 读口 + RFC vs 2 读口，MaxFlops 差 **44%** | 读带宽就是紧约束 ⇒ `W = 2` 是真值 |

⇒ **NVIDIA 用「复用」补上了 `W = 2` 相对峰值的缺口；OSF 的 MCOS 是同一件事的加强版**（read-once → 多消费者）。

**达成的可验收条件**（33 号文档 §4.1.4c）：

| 条件 | 不满足 | 满足 |
|------|--------|------|
| ① 复用机会存在（编译器复用意识，I3） | `r = 3` → IPC **0.667** | `r = 2` |
| ② `budget_hint` 正确 | 消费者 MISS → `r` 仍 3 | `r = 2` 成立 |
| ③ 剩余 2 源跨 bank | `max_b_avg = 2` → IPC **0.500** | `max_b_avg = 1` |
| **合计** | — | **IPC = min(1, 2/2, 1/1) = 1.000** |

**附带效果**：`r = 2` 且跨 bank ⇒ 每 bank 平均负载恰 1.0 槽/指令 ⇒ `max_b_avg = 1` ⇒ **bank 冲突气泡归零** ⇒ **MCOS 同时解决带宽瓶颈与冲突气泡**。

> ⚠ **诚实的失败模式**：无复用机会的负载（如寄存器压力极大的标量代码）在 `W = 2` 下**恒停在 0.667**。这是"不加第 3 个读口"的直接代价，**硬件无法弥补**（编译器是唯一能创造复用机会的主体）。

### 4.2 与上游实测的弹性对照（**给 IPC 目标打折**）

| 上游实测 | 寄存器读次数 | IPC | 弹性 `ΔIPC% / Δ读%` |
|---------|------------|-----|-------------------|
| CORF | **−10%** | **+4%** | **0.40** |
| CORF++ | **−23%** | **+9%** | **0.39** |

**模型在"读带宽是唯一瓶颈"时弹性 = 1.0；实测只有 ≈ 0.4。**

**原因**：真实 kernel 里读带宽**未必是唯一瓶颈**（发射宽度、ALU 吞吐、延迟隐藏、访存都可能先饱和）。

**⇒ 33 号文档 §6 的 IPC 目标应取模型值（+50%，弹性 1.0）与实测弹性（0.4）之间**，不应按线性外推承诺 +50%。

### 4.3 适用边界汇总

| 负载形态 | 读端口占用 | 发射率 | OSF 的 IPC 收益 |
|---------|----------|-------|--------------|
| **3 源密集**（FFMA / GEMM / 矩阵类） | 100%（饱和） | **0.667** | **+50%（`W=2`）**；`W=3` 时为 0 |
| **2 源密集**（FADD / FMUL / 标量-向量混合） | 100%（饱和） | **1.000** | **0%** |
| 混合 | 波动 | 波动 | 取决于 3 源占比 |

## 5. 时序过程（cycle 坐标）

### 5.0 坐标约定

| 记号 | 定义 |
|------|------|
| `dispatch(i)` | 调度器把指令 i 送上分配级的那一拍 |
| **`issue(i)`** | **指令 i 离开 Allocate、端口预约成功的那一拍** —— **一切时序公式的坐标原点** |
| `L` | 读源窗口长度 = **3** |
| `d` | ALU / FU 占用深度 = **1**（**v1.1 已裁决**，33 号文档开放项 O-2 关闭）：Ampere FU 为**全 warp 宽 → 1 拍占用**（arXiv:2503.20481 §5.1.1 原文） |
| `t` | `issue(i)` 的简写 |

**固定关系**：

```
值到达 ≤ t+2   →   Execute 进入 = t+3   →   结果可用 = t+4
                              →   RF 写回 + MCOS FILL = t+4
                              →   消费者最早发射 = t+4（bypassing）→ 依赖链率 = 4 cycle/条 ✔ 与 P1 实测一致
```

> **气泡的坐标含义**：上游压气泡时，被推迟的是**后续指令的 `dispatch`**；被卡在 Allocate 的那条指令，其 `issue` 整体后移，**`Execute = issue + 3` 仍成立**。
> **IPC 的分子**是"**成功分配**的指令数"，不是 dispatch 数。

> **`d` 的取值依据与上游「5/6/7」的真身（v1.1）**：
> - Ampere 论文 §5.1.1 原文：FU 的输入 latch「occupied for **two cycles** if the width of the execution unit is just half warp, and for **one cycle if its width is a full warp**」⇒ Ampere FP32 FU 全 warp 宽 ⇒ **`d = 1`**。
> - 定长指令的依赖延迟**实测 = 4**（论文 §4，且经 Stall counter 语义验证：设错会导致程序结果错误）。
> - **「5/6/7」不是 issue→result 延迟**——它是论文 Listing 1 那 **6 条指令序列的 elapsed**（5 = 「the minimum since each sub-core can issue one instruction per cycle」；6/7 = bank 冲突多出的 1/2 拍**气泡**）。⇒ v1.0 曾据此推出「`d = 2`、与实测差 1 拍」的结论**作废**。
> - ⇒ `Execute = issue+3`、结果可用 `= issue+4`、**链率 4 cycle/条** 与实测完全自洽。

### 5.5 图 5 — MCOS 在时序上的落点（FILL / INVALIDATE / CONSUME）

```
生产者 P 写 R：
        t+3            t+4                    t+5        t+6
        │              │                      │          │
        │  P Execute   │ 结果可用              │          │
        │              │ INVALIDATE(R)：清 R 在该 bank 所有 op_pos 的槽
        │              │ FILL(R, k)：槽 LIVE，budget = budget_max 或 1
        │              │                      │          │
消费者 C 发射 ────────────────────────────────────────┼──────►│
  （C 的 RF 读窗口 [t+5, t+7]）                    │      │ CONSUME(R,k)：命中 → 交付槽值，budget--
                                                    │      │ ⚠ 若 P 的写回落在 C 的读窗口内，
                                                    │      │   C 读到旧值（程序序正确）：
                                                    │      │   → 33 号文档 §5.1 C-5（WAR 依赖计数器，
                                                    │      │     读完源操作数时释放；写者等计数器归零）
```

**时序上的三条要点**：

1. **FILL 与 RF 写同拍**（`t+4`）→ 槽在生产当拍即可被消费者取用；MCOS 命中即**不占 bank 槽** —— **这正是 IPC 从 0.667 升到 1.000 的物理原因**。
2. **INVALIDATE 先于 FILL**（C-3）→ 同拍内先清旧值的所有 op_pos 槽（防陈旧值残留）再填新值；**但它不得清零 `demand_miss`**（否则自适应通道成为死代码，33 号文档 v0.4 B2）。
3. **WAR 窗口必须被规范定义**（33 号文档 §5.1 C-5~C-7）→ 消费者读到**旧值**（`issue` 拍锁存），程序序正确。

## 附录 C：复算脚本

本文全部表格由下述脚本生成（**Python 3 标准库，零依赖**）。可直接复制运行以复现全部数字：

```python
#!/usr/bin/env python3
"""SM 操作数供给 IPC 模型（per sub-core）—— 复算 34 号附录的全部表格。
模型: IPC_max = min(I_issue, W/r, 1/max_b_avg)
"""
from fractions import Fraction as F


def ipc(k, W, I=1, hits=0, pattern=None):
    r = k - hits
    if pattern is None:                       # 源在 2 个 bank 上尽量均分
        b0 = r // 2
        pattern = [(b0, r - b0)]
    loads = [F(0), F(0)]
    for (b0, b1) in pattern:
        loads[0] += b0
        loads[1] += b1
    n = len(pattern)
    max_b_avg = max(loads) / n
    bounds = {
        "发射宽度": F(I),
        "读带宽总量": F(W) / r if r > 0 else F(0),
        "单bank槽位": F(1) / max_b_avg if max_b_avg > 0 else F(0),
    }
    binding = min(bounds, key=lambda kk: bounds[kk])
    return bounds[binding], r, max_b_avg, binding


def show(title, k, W, hits=0, pattern=None):
    v, r, mb, binding = ipc(k, W, hits=hits, pattern=pattern)
    print(f"{title:<40} r={r}  max_b_avg={float(mb):<6.3f} "
          f"IPC={float(v):<6.3f}  瓶颈={binding}")


if __name__ == "__main__":
    print("表 1 — 连续 3 源序列 (FFMA), W=2")
    show("均衡(交替 2+0 / 0+2)", 3, 2, pattern=[(2, 0), (0, 2)])
    show("固定 2+0", 3, 2, pattern=[(2, 0)])
    show("三源全同 bank", 3, 2, pattern=[(3, 0)])
    show("MCOS: 1 个操作数被复用", 3, 2, hits=1, pattern=[(1, 0)])
    show("MCOS: 2 个操作数被复用", 3, 2, hits=2, pattern=[(1, 0)])

    print("\n表 2 — 连续 2 源序列 (FADD/FMUL), W=2")
    show("两源跨 bank", 2, 2, pattern=[(1, 1)])
    show("两源同 bank", 2, 2, pattern=[(2, 0)])
    show("MCOS: 1 个操作数被复用", 2, 2, hits=1, pattern=[(1, 0)])

    print("\n表 3 — W 敏感性")
    for W in (1, 2, 3):
        show(f"W={W} 连续 3 源 (均衡)", 3, W, pattern=[(2, 0), (0, 2)])
        show(f"W={W} 连续 2 源 (跨 bank)", 2, W, pattern=[(1, 1)])
        show(f"W={W} 3 源 + MCOS(1 复用)", 3, W, hits=1, pattern=[(1, 0)])
        print("-" * 78)

    print("\n自洽性验证 — 由实测气泡反查 max_b 与稳态 IPC")
    for label, max_b, exp in [("FMUL 跨 bank", 1, 0), ("FMUL 同 bank", 2, 1),
                               ("FFMA 三源同 bank", 3, 2), ("FFMA 2+1 (推得)", 2, 1)]:
        pattern = [(max_b, 0)] if max_b > 1 else [(1, 1)]
        v, r, mb, b = ipc(len(pattern[0]), 2, pattern=pattern)
        print(f"{label:<20} max_b={max_b} 气泡={max_b-1}(实测{exp}) "
              f"稳态IPC={float(v):<6.3f} 延迟=5+{max_b-1}={5+max_b-1}")

    print("\nCORF 弹性对照")
    for name, dr, dipc in [("CORF", -10, 4), ("CORF++", -23, 9)]:
        print(f"{name:<8} 读 {dr:+d}% -> IPC {dipc:+d}%   弹性 = {dipc/abs(dr):.3f}")
```
