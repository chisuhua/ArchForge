## 1. 组 A —— Q-3 五问（阻塞项，本轮全部交付）

> **背景复述**：CppTLM 回执指出，本仓 `32 号 §5.2` 断言 `moesi_gpu` 的 `E→M`「是一个域可见写」，

> 本节逐条补齐，并给出 Q-3a 要求的「转发请求在 MOESI 下的具体形态」。

### 1.1 Q-3a

> **问**：`moesi_gpu` 的 `E → M`：`E` / `M` 是否**接受**「导致**数据值响应**的转发请求」？
> 若是 → 给出该转发请求在 MOESI 下的**具体形态**（canonical 流号 / 消息类 / 方向）。

**答复：是 —— 判据 (b) 成立。**

**(1) 判据的代入**

`ADR-CEP-13` 决策 3 的判据原文（`docs/adr/ADR-CEP-13-coherence-domain-ownership.md:99-103`）：

> 请求 `r` 是**域可见写** ⟺ **(a)** 终态 `s1` 允许 store **命中且无需外部通信**（可能转到 `s2`）
> **且 (b)** `s1` 或 `s2` 接受"导致**数据值响应**的转发请求"

代入 `moesi_gpu` 的 `E → M`（`docs/architecture/09-coherence-protocol.md:152`，E 行第 2 列 = `3`）：

| 符号 | 取值 | 含义 |
|------|------|------|
| `s1` | `E` | store 命中时的状态（`E` = 唯一副本、干净） |
| `s2` | `M` | 静默升级后的状态（`M` = 唯一副本、脏） |

**(2) 判据 (a)** ✓ —— `E` 是**唯一副本且干净** → store 直接就地命中并升级为 `M`，**不发出任何外部通信**。

**(3) 判据 (b)** —— 判据是**析取**（`s1` **或** `s2`），逐态评估：

| 状态 | 接受「导致**数据值响应**的转发请求」？ | 依据（本仓文档级语义） |
|------|--------------------------------------|------|
| `E` | **否** —— 干净独占态；snoop 响应是 `ACK`，**不带数据**（数据由内存提供） | `docs/microarchitecture/coherence-protocol.md:255-263`（`handle_probe` 的 `case CoherenceState::E` → `SnoopResp::ACK`）；`:219` / `:221`（E + snoop(READ_SHARED / INVALIDATE) → `S` / `I`，**无 data 转发**） |
| `M` | **是** —— 脏独占态；snoop 响应是 `DATA_AND_ACK`，**携带数据值** | `docs/microarchitecture/coherence-protocol.md:265-275`（`case CoherenceState::M` → `DATA_AND_ACK`，`:269` / `:272`）；`:224` / `:226`（M + snoop(READ_SHARED) → `O`，**data 转发**；M + snoop(INVALIDATE) → `I`，**data 写回**） |

→ `s2 = M` 成立 ⇒ 判据 (b) **整体成立**（析取的一支为真即可）。
→ 与 (a) 合取 ⇒ **(a) ∧ (b) 成立** ⇒ `E → M` **是域可见写** ⇒ 跨 D-GPU / D-FABRIC 边界时**必须触发跨域传播**。

**(4) 转发请求在 MOESI 下的具体形态**（回答贵方要求的「canonical 流号 / 消息类 / 方向」）

| 项 | 内容 |
|----|------|
| **转发请求** | **snoop**（canonical **流 3**，消息类 `snoop`），类型 `READ_SHARED` / `READ_EXCLUSIVE` / `INVALIDATE` |
| **方向** | **center → node**（CoherentXBar / Sharer Tracker → 持有该行的 cache） |
| **数据响应** | **snoop_resp**（canonical **流 4**，消息类 `snoop_resp`），响应类型 `DATA_AND_ACK`，**携带数据值** |
| **方向** | **node → center** |
| **数据承载** | canonical **流 6** `forward_data` —— 与 snoop **同槽**（`compute_noc` VC2 = `snoop` + `forward_data`，per `32 号 §6.0.2`）；即「snoop 槽同时承载转发数据」（`forward_data` **不单列**，per `32 号 §6.0.1`） |
| **MOESI 语义** | `M` 持唯一脏副本 → 收 `READ_SHARED` → `M→O`（+requester）并**转发数据**；收 `INVALIDATE` → `M→I` 并**写回数据** |

**(5) 为什么这条对跨域要紧（机制链）**

静默 `E → M` 之后，D-GPU 侧的 cache 处于 `M` 态 → 它**具备向其他域供给数据的能力**（`M` 的 snoop 响应带数据）→
D-FABRIC 的一次读若经跨域桥接转发到该 cache，**必然读到新值**；而这条路径**没有任何跨域传播请求被发出**
（静默升级对 center 不可见）→ 写因此**跨域可见而未被传播** → CEP 的 4 值 `perm` 无法表达「这是静默升级」→ **R-2 命中**。

**(6) 两点必须声明的边界**（避免把结论读大）

1. **结论层级 = 声明层**：`moesi_gpu` 插件**尚无实现**（本仓 `09 号 §5.3` 仍为规划态），
   (b) 的评估依据是本仓**文档级**的 snoop 响应语义（`coherence-protocol.md §4` 表 + `§5.1` `handle_probe`）。
   实测确认依赖 PoC **S2**（见 [Q-3e](#15-q-3e)）。
2. **`E` 本身不成立** —— 这与 RC 反例同形（valid / 干净态不提供数据）。
   **是 `M` 态的「脏 + 可供给数据」属性让判据 (b) 成立** —— 即 (b) 落在**协议状态机的响应语义**上，
   不落在状态名的直觉上。**这条也说明**：换一个协议的 `E` 语义（若其 `E` 也带数据响应），(b) 的结论会不同
   → 判据 (b) 必须**逐协议实例**评估，不能跨实例外推。

**(7) 对本仓原有结论的修正**（主动认领）

`32 号 §5.2` 的原文本是「满足判据 (a) → 因此它**是一个域可见写**」—— **推理链缺 (b) 一环**。
结论方向**不变**（`E → M` 确实是域可见写），但论证链现在闭合。已在
[`32 号 §5.2.1`](../architecture/32-cep-based-coherence-architecture.md) 落地（见 §4 写回 #1）。

### 1.2 Q-3b

> **问**：若 (b) **不成立**，你方是否**仍**要求 `perm` 加「可静默升级」判别位？

**答复：前提不适用（本轮 (b) 成立）；R-2 保留，且等级升格。**

- 问法的前提是「若 (b) 不成立」→ 本轮 (b) **成立** → 前提不适用。
- **即便走「不成立」的分支，R-2 的需求本体仍独立成立** —— 这与贵方 PoC 规格 **S1** 的失败含义**完全一致**：
  「`perm` 4 值投影的表达力不足 → R-2 的**需求本体**成立（**与 (b) 的评估无关**）」。
  即：**两侧在这一点上原本就没有分歧**。
- 但本轮 R-2 的**等级变了**：从「潜在表达力缺口，尚未证实触发」→ **「已触发」**
  （`ADR-CEP-05 §7` 判据 2 的触发条件被满足）。
- 我方**不撤回** R-2。`perm` 的建议落点维持 `32 号 §11 R-2` 的「对象数组 `[{value, silent_upgrade_to}]` 或新增顶层字段」，
  但**补充一条约束**（这是本轮评估带出的新信息）：
  该字段必须能表达「**本行的 `UNIQUE` 投影可静默升为 `WRITEBACK`**」这一**具体**语义（`E→M`），
  而**不是**一个泛化的「可升级」布尔 —— 因为 `O→M`（`coherence-protocol.md:228`：O + write → M，需 `INVALIDATE→others`）是**显式**升级
  （需 invalidate 其他 sharer、发出外部通信），二者对跨域传播的触发条件**不同**。
